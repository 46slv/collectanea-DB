# 外部モニタリング：画面が違えば、グレードを変える前に経路を確認する

ColorページのViewerでは適切に見える映像が、外部モニターでは暗く、別のPC画面では彩度が高く見えることがあります。このとき先にグレードを変更すると、納品先では逆方向の問題が生じかねません。最初に確認するのは、**同じ映像を、どの信号経路と表示条件で見ているか**です。

DaVinci Resolveには作業画面でのプレビューに加え、Blackmagic DesignのDeckLink／UltraStudioによるSDI・HDMI映像出力などのモニタリング経路があります。公式Colorページは、こうした機器を色が重要な制作向けの入出力手段として紹介しています。ただし、**専用出力を使うだけでモニターの色が自動的に正しくなるわけではありません**。表示機器の状態と信号設定は別に確認します。

ここでは機種比較ではなく、補正結果を判断するための表示経路、確認順序、異常時の切り分けを扱います。[カラーマネージメントの基礎](../learn/color-management-basics)は入力・作業・出力変換、[書き出し後の色ズレ](../troubleshooting/export-color-mismatch)は完成ファイルの検査を扱っています。

## まず3種類の「画面」を区別する

| 確認している場所 | 何を見ているか | 判断時の注意 |
| --- | --- | --- |
| **ColorページのViewer** | Resolveの編集UI内に描画されたプレビュー | OS、GPU、ディスプレイ設定などを含む表示経路と納品出力の条件を同一視しない |
| **PCディスプレイのフルスクリーン表示** | PC画面を大きく使うプレビュー | フルスクリーン化しただけでは専用ビデオI/Oの出力にはならない |
| **DeckLink／UltraStudioによる映像出力** | 映像I/O機器から外部表示機器へ送る信号 | 接続形式、映像フォーマット、表示機器のモード・校正状態まで確認する |

Blackmagic Design公式Colorページは、無料版での単一画面のフルスクリーン再生と、Studioによる2台目のPCディスプレイでのフルスクリーン再生に言及しています。これは公式サイト掲載時点の製品説明です。**Resolve 21.1での具体的なメニュー操作、OS別の挙動、ビデオI/O機器ごとのライセンス条件をこの記述だけから断定しません。**

PCデスクトップをHDMIでテレビへ複製しても、DeckLink等のビデオ出力経路を使用したことにはなりません。ケーブル名ではなく、映像を送り出しているデバイスと表示までの処理経路で分類します。

## 比較条件を固定する

### 1. 納品先を決める

作品をSDRのWeb配信、放送、HDR配信など、どの条件へ納品するかを先に確認します。映像の原色、伝達特性、信号レンジ、HDR／SDRの別は「Rec.709」や「4K」だけでは確定しません。納品仕様がある場合はそれを優先します。

[Color Space Transform（CST）](./color-space-transform)を手動で置く場合、プロジェクトのColor ManagementによるOutput変換と同じ役割を二重に適用していないか点検します。変換前のLog画像を表示用画像と比較しても、モニターの精度は判断できません。

### 2. 同じフレームを比較する

画面内に肌、ニュートラルに近い面、暗部、明部、彩度の高い物体が含まれるショットを選びます。グレーカードやカラーチャートがあれば参照できますが、撮影条件が不明な白い壁を中立基準と決めつけません。

同じタイムコードの静止フレームで比較してから動きのある部分を再生します。別フレーム、別カット、異なるグレードのStillを見比べると、表示差と素材差を混同します。

### 3. 出力変換の場所を確認する

Color ManagementのInput／Timeline／Output、Clip・Group・TimelineのCSTやLUTの用途を確認します。Output変換をどこが担当し、その結果をどの画面へ渡しているかを説明できる状態にします。

「Viewer用だけの変換」「モニター側の表示LUT」「納品ファイルへ焼き込む変換」は目的が異なります。**表示確認のためだけのLUTを納品結果へ誤って適用すること**と、変換済み信号の二重変換を避けます。21.1の具体的な表示LUT設定名や適用順序は未照合です。

### 4. 映像出力と表示機器を確認する

専用ビデオI/O経路を使う場合は、機器と表示機器が想定する信号フォーマットに対応しているか確認します。解像度・フレームレートに加え、色の解釈、信号レンジ、HDRモードを区別します。公式ページで紹介される機器の最高仕様を全製品の共通能力として扱いません。

表示機器では入力ごとの画質モード、ホワイトバランス、ガンマ／EOTF、色域、輝度、HDR設定を記録します。利用できれば対象規格に合う測定・校正結果を確認します。校正なしに「見た目が自然」というだけでリファレンス表示の正確さを証明することはできません。

室内照明、外光、視聴位置を比較時に変えず、表示機器の自動輝度や省電力処理によって条件が動かないか確認します。

### 5. Scopesと目視の役割を分ける

[Scopes](./scopes)のWaveformは階調、RGB Paradeはチャンネルの偏り、Vectorscopeは色相・彩度の傾向を調べるために使います。公式Colorページもこれらの用途を示しています。

Scopesが表示するのはResolve側で扱う画像信号の情報であり、**外部モニターが実際にどの色や輝度で光っているかの測定値ではありません**。信号の表示が一定なのに外部画面だけ違う場合、Colorホイールを動かす前に信号経路とモニター設定を調べます。

## 実践：外部だけ肌色が赤く見える

インタビューをViewerと外部モニターで見比べ、外部だけ肌が赤く見える場合を想定します。

1. 同じショット・同じフレームへ固定します。[Gallery／Stills](./gallery-stills)で別のグレードを比較していないかも確認します。
2. PCのGPUからのディスプレイ接続か、DeckLink／UltraStudioからの映像出力かを記録します。
3. ProjectのOutput変換、ノード内のCST／LUT、外部表示側の色モードを調べます。
4. RGB ParadeとVectorscopeで信号を観察します。Scopesだけで肌色の絶対的な正しさは判定しません。
5. 入力別の表示モードや自動補正を調べ、元の設定を記録したうえで条件を一つずつ変更します。
6. 原因が分かるまで、赤さを相殺する目的でクリップの色を逆方向へ調整することは保留します。

これは判断例であり、21.1と特定モニターを使用して測定した結果ではありません。必要なら外部測定器による校正・信号検査を行います。

## 症状別の切り分け

| 症状 | 最初に調べること | 断定しないこと |
| --- | --- | --- |
| Viewerだけ明るい／暗い | PC画面の表示設定、映像出力方式、Output変換の比較条件 | 片方が必ず正しいという判断 |
| 外部だけ色が偏る | 入力別モード、校正、信号解釈 | Clipの色かぶりが原因という判断 |
| HDRで暗い／明るい | HDR／SDR指定、伝達特性、HDRモード、表示側のマッピング | 固定ガンマ値で解決するという判断 |
| 黒が浮く／詰まる | 出力と受信側のレンジ解釈、表示条件、Output変換 | 無条件にFull／Videoを切り替えること |
| 再生時だけ違う | 自動輝度、映像処理モード、フレーム間の補正変化 | 静止画が一致すれば全編も一致するという判断 |
| 書き出しだけ違う | 実ファイルの再読み込み、色タグ、エンコード、再生側 | モニター設定で出力ファイルも修正されるという判断 |

書き出し後の差は[書き出し後に色や明るさが違うとき](../troubleshooting/export-color-mismatch)、ショット間の補正漏れは[納品前のColor QC](../recipes/pre-delivery-color-qc)へ進みます。

## 記録と終了判定

日付、Resolveの正確な版、Input／Timeline／Output、比較フレーム、出力デバイス・接続、表示機器名・入力・モード、SDR／HDR、校正条件、症状と再確認結果を残します。

カラー設定を変更したら同じフレームで再比較し、意図した納品仕様と実ファイルの検査を別に行います。**モニタリングの一致は、ファイル納品の正しさと同義ではありません**。
