# Color Tracker（Power Windowを動きに追従させる）

Colorページの**Tracker**は、動く被写体に合わせてPower Windowを移動・変形させるための機能です。顔を明るくするために作ったWindowが、人物の移動後も顔から外れないようにする、といった用途に使います。静止画の1フレームで補正範囲を決めるだけでは、ショットの途中で対象がWindowから外れることがあります。

[Power Windows](./power-windows)が「どの位置・形へ補正をかけるか」を決めるのに対し、Trackerは「時間が進んだときにその範囲をどのように動かすか」を扱います。**追跡に成功しても、色補正の強さや境界の自然さまで自動で最適化されるわけではありません。** トラッキング結果とグレードの見え方をそれぞれ確認します。

## Trackerを使う場面と、使わなくてよい場面

- **固定カメラで被写体もほぼ動かない**：まず静的なWindowだけで十分かを確認します。
- **人物の顔や服が画面内を移動する**：Windowを追従させる目的でTrackerを使います。
- **カメラがパン・ティルト・ズームする**：画面上の対象の位置や見かけの大きさが変わるため、移動だけでなく変形も確認します。
- **被写体が隠れる、画面外へ出る、形が大きく変わる**：自動追跡を過信せず、ショットの該当区間を個別に点検します。

Trackerは被写体の意味を理解して「顔であること」を常に維持する選択ツールではありません。形と位置で定義したWindowが追従できているかを、Viewerの時間方向の変化から判断します。色による選択が適切なら[HSL Qualifier](./hsl-qualifier)とWindowを組み合わせる方法もあります。

## Colorページでの基本操作

Blackmagic Design公式Colorページが示すPower Windowの追跡手順を、補正作業の順番に沿って整理します。

1. Colorページで対象クリップを選び、まず[Primaries](./primaries-color-wheels)や[Scopes](./scopes)で全体の状態を確認します。局所補正は独立したシリアルノードへ分けると、追跡結果とベース補正を比較しやすくなります。
2. そのノードの**Windowパレット**で対象を囲むPower Windowを作ります。顔ならCircularを出発点とし、動く前のフレームで位置と大きさ、Softnessを合わせます。
3. **Windowを選択したまま、ツールバーの十字形アイコンからTrackerパレット**を開きます。
4. パレットの解析オプションで、対象の見かけの動きに合うものを選びます。公式Colorページでは**Pan、Tilt、Zoom、Rotate、Perspective（遠近3D）**に相当する解析対象が示されています。必要な運動成分は映像によって異なります。
5. ショットの冒頭まで再生ヘッドを移し、**順方向のトラッキング（Track Forward）**を実行します。Resolveがクリップを解析し、Power Windowの動きを自動で設定します。
6. 解析後はViewerを再生・スクラブし、**冒頭、中間、終盤、最も大きく動く箇所**でWindowが対象を囲んでいるか確認します。境界のずれが見つかったら、その周辺を重点的に見直します。
7. Windowに対して明るさ・色の補正を加え、ノードの有効／無効を切り替えて、補正の追従と画面全体の自然さを比較します。

これは**クリップ冒頭から順方向に解析する標準的な流れ**です。途中フレームを起点にした逆方向の解析や、トラッキングデータの編集・削除に関するボタン名と挙動は、本記事では21.1実機未確認のため断定しません。

## Pan／Tilt／Zoom／Rotate／Perspectiveをどう考えるか

Trackerのオプションは、追跡対象が画面上でどのように見えるかを考えるためのものです。すべての項目を同時に使うことが常に最良とは限りません。

| 動きの見え方 | 確認したい成分 | Viewerでの判定 |
| --- | --- | --- |
| 画面の左右に動く | Pan | Windowの左右位置が対象に合っているか |
| 画面の上下に動く | Tilt | 頭部や物体から縦方向にはみ出さないか |
| 近づく／遠ざかる | Zoom | 対象の大きさに合わせてWindowが変化するか |
| 画面内で傾きが変わる | Rotate | 顔や物体の傾きにWindowが追従するか |
| 斜め向きになるなど見かけの形が変わる | Perspective | 平面の向きの変化に範囲が合っているか |

上表は**解析オプションを選ぶための観察例**です。各オプションの内部アルゴリズム、優先順位、数値範囲、初期状態を説明するものではありません。対象の輪郭が大きく変形する場合や、別の物体と交差する場合は、追跡した移動だけで補正範囲が適切とは限りません。

## 例1：歩く人物の顔だけを少し明るくする

屋内を横切る人物の顔が暗いショットを想定します。全体を明るくすると背景が明るくなりすぎるため、顔に限定した補正を使います。

1. 全体の露出と色を整えたノードの後に、**顔用ノード**を追加します。
2. 顔より少し広めのCircular Windowを置き、背景になじむSoftnessを設定します。髪の生え際にぴったり沿わせる必要はありません。
3. Trackerで人物の横移動に対応する解析を行います。顔がカメラへ近づくなど大きさも変わる場合は、サイズの追従も結果を見て判断します。
4. ショットを通してWindowを確認します。歩く人物が他の物体の後ろを通る区間、振り返る区間、速度が変わる区間では特に注意します。
5. 顔の明るさを少し調整し、Windowの位置が合っていても背景が不自然に持ち上がっていないか確認します。

完成の判断は「顔が読み取りやすくなり、**再生中に補正の境界が移動して見えない**」ことです。Trackerが完走したという表示だけでは完成とは判断しません。

## 例2：パンするショットの窓明かりを抑える

カメラが横に振られ、画面内の明るい窓が位置を変えるショットを想定します。

1. 窓の周辺へ形の合うPower Windowを配置し、明るさを抑える補正を別ノードで準備します。
2. カメラのパンに伴う移動をTrackerで解析し、窓が画面の端に寄るフレームや一部が隠れるフレームを確認します。
3. Windowが壁や人物へ移ってしまう場面では、補正をそのまま通し続けず、その区間のWindow配置や適用範囲を見直します。
4. 補正のオン／オフを切り替え、窓の外側に不自然な明暗の帯が見えないか確認します。

この例では**追跡精度と補正量**を別々に調整します。Windowの位置が合っていても、Softnessが足りない、補正を強くかけすぎた、といった理由で結果が不自然になることがあります。

## 追跡後の確認順序

失敗したときは、最初から追跡設定をすべて変えず、次の順で原因を分けます。

1. **Windowの初期位置**：解析開始時に、目標と関係のない場所を囲んでいないか。
2. **対象の見え方**：移動だけでなく、大きさや角度が変わっていないか。遮蔽やモーションブラーで追う手掛かりが失われていないか。
3. **時系列**：開始直後は合うのに後半でずれるのか、遮蔽物の前後だけでずれるのか。
4. **補正の見え方**：Windowの位置は正しいのに、Softnessや補正量によって境界が見えていないか。
5. **選択範囲の条件**：Qualifierを併用している場合、色の選択が消えたことをTrackerの失敗と取り違えていないか。

| 症状 | 最初に見る点 | 対応の方向 |
| --- | --- | --- |
| 追跡の初めから別の場所を囲む | Windowの初期配置、対象の識別しやすさ | 解析前の配置を見直す |
| 後半になるほどずれる | 画面内の移動・大きさ・角度の変化 | 動きに合った解析条件と区間を再点検する |
| 遮蔽後に背景へ補正が残る | 物体が隠れる前後のフレーム | 問題区間の適用範囲を個別に直す |
| Windowは合っているのに輪郭が目立つ | Softness、補正量、色差 | トラッキングではなく補正側を調整する |
| 全体の明るさも一緒に変わった | 局所補正と一次補正のノード分離 | ノードの役割を分けて比較する |

追跡は「解析を実行したら終了」ではありません。クリップを流して見たときの補正結果を最終基準とします。

## Trackerとほかの機能を混同しない

- **Power Window**：画面の位置と形で補正領域を作る。[Power Windows](./power-windows)を参照。
- **Tracker**：Power Windowの位置・形の変化を時間方向に追従させる。本記事の対象。
- **Qualifier**：色相・彩度・輝度などの画素条件で領域を選ぶ。[HSL Qualifier](./hsl-qualifier)を参照。
- **Stabilization**：映像全体の揺れを抑える別の目的。Blackmagic Design公式ColorページではTrackerに関連する用途として紹介されていますが、Window追従と同じ完成条件ではありません。
- **Magic Mask**：被写体の選択を扱う別の機能。本記事の手順はMagic Maskの使い方や対応エディションを説明するものではありません。
