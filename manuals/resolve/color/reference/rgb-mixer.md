# RGB Mixerで色チャンネルを混ぜる

RGB Mixer（RGBミキサー）は、映像の赤・緑・青のチャンネルが、出力の色にどれだけ寄与するかを調整するColorページのパレットです。露出やホワイトバランスを整える[Primaries](./primaries-color-wheels)と異なり、色チャンネル同士の関係を変えて、意図的な色かぶりや独特のモノクロを作るのに使えます。

Blackmagic Designの[公式Colorページ](https://www.blackmagicdesign.com/jp/products/davinciresolve/color)は、スライダーでRGBの量を変える操作、チャンネルの交換、「モノクロ」設定を案内しています。本記事ではそれらを使い分ける判断方法を説明します。具体例は制作上の想定であり、Resolve 21.1実機で検証済みの設定値や作例ではありません。

## 何を変えるパレットなのか

通常のカラー映像には赤（R）・緑（G）・青（B）の色成分があります。RGB Mixerでは、結果のあるチャンネルに元の色成分をどの程度利用するか、という観点で調整します。たとえば赤系の出力に緑や青の成分を加えるような方向へ変えると、赤だけの強弱では説明できない色の変化が起こり得ます。

この「色の寄与」という説明は理解のための概念モデルです。21.1内部の行列演算・クリッピング・係数の正確な式、UIの個別初期値は、公開Colorページだけでは確定できません。ここでは架空の数値プリセットを提示しません。

| 目的 | 最初に検討する操作 | RGB Mixerを選ぶ理由 |
| --- | --- | --- |
| 全体の露出と白バランスを整える | [Primaries](./primaries-color-wheels) | 色チャンネルの混合まで変えたい場合 |
| 特定の色相や彩度を限定して変える | [HSL Curves](./hsl-curves) | 色同士の関係を広く変えるLookを作りたい場合 |
| 衣服など一部分だけ補正する | [Qualifier](./hsl-qualifier)／[Window](./power-windows) | 対象を限定したうえで混合したい場合 |
| 白黒で色ごとの明るさを演出する | RGB Mixerのモノクロ | 元のR/G/Bの寄与を明暗として利用したい場合 |

## 操作前にノードの役割を分ける

RGB Mixerの変化を評価するときは、技術的な色変換と見た目のLookを混ぜない方が判断しやすくなります。

1. Colorページで対象クリップを選び、[Node Graph](../learn/color-node-graph)に、基本補正と別のLook用シリアルノードを用意します。
2. [カラーマネージメント](../learn/color-management-basics)を確認し、Input／Timeline／Outputの変換やCSTとLookを区別します。RGB MixerをLogから表示用色空間への変換の代用品にはしません。
3. Look用ノードでRGB Mixerを開きます。先にViewerで白・肌・背景の色を見て、[Scopes](./scopes)のRGB Paradeでも変化前の分布を確認します。
4. 一度に大きく複数のチャンネルを変えず、まず一つの調整方向を試します。変えたチャンネルと、関係のなさそうな物体まで色が変わっていないか観察します。
5. ノードの有効／無効で差を比較し、意図した変化だけが得られたか確認します。画面が派手になっただけなら量を戻します。

色管理の前提や素材によって結果の見え方は異なります。RGB Paradeの3成分が一致することも、すべての場面で正解という意味ではありません。

## 例1：夜景の色かぶりをLookとして調整する

都市の夜景を少し冷たい印象にしたいとします。青い成分の寄与を変える方向を試しながら、白い看板や人物の肌まで不自然に変えないことを目標にします。

1. Primariesで露出と大きなホワイトバランスの問題を整理します。撮影時の色のずれを技術的に直したいだけなら、まず基本補正の範囲で判断します。
2. 別ノードのRGB Mixerで青系の見え方が変わる方向を少しずつ試します。何を変えたか分かるよう、一つの調整の結果を観察してから次へ進みます。
3. Viewerで看板の白、人物の肌、夜空、街灯の色を見ます。RGB Paradeでは変化の傾向を確認しますが、もともと青い光を無理にニュートラルへ戻しません。
4. 肌が大きく不自然になったり、照明の色が失われたりしたら調整量を戻します。必要なら局所補正を分ける方が適切です。
5. 前後のショットも再生し、同じシーンの中で色が急に変わらないか確認します。

**判断例：** 冷たい夜景のLookは得られても、白い字幕や肌まで意図せず色づくなら、チャンネルの混合量か補正対象を見直します。単純に全体を少し青くしたいだけなら、Primariesの方が操作の意味を把握しやすい場合があります。

## 例2：緑の木を明るく、青い空を暗くしたモノクロ

Blackmagic Design公式Colorページでは、RGB Mixerの「モノクロ」を有効にして元のRGB成分の輝度への寄与を変える作例が説明されています。緑の寄与を上げ、青を下げることで、木々を明るく、空を暗く表現する例です。

1. 緑の葉と青い空が共に見える素材を選び、変換前の色と明暗を確認します。
2. Look用ノードでRGB Mixerの「モノクロ」を有効にします。
3. 緑成分を強める方向に調整し、葉が明るくなったときに枝や地面との階調が残るか確認します。
4. 青成分を弱める方向に調整し、空の暗さと雲の階調を見ます。空の情報が失われるなら弱めすぎです。
5. 赤成分も含めて全体を見直し、ViewerとWaveformで白飛び・黒つぶれが起きていないか確認します。

**判断例：** 木は白く浮き、空は暗いが、葉の細部が白一色になった場合、見た目のコントラストだけで成功と判断しません。木・空・地面が区別でき、必要な階調が残るところまで戻します。

モノクロにするときに重要なのは色を単に消すことではなく、**元の色成分の違いをどの明暗に写すか**です。紅葉や曇天の素材では同じ調整方向でも結果が異なるため、固定の推奨係数は使いません。

## 例3：強い色を使ったグラフィックの印象を試す

RGB Mixerは、Blackmagic Design公式ページでも画面上のグラフィックの見え方を変える用途として紹介されています。色数が少ないロゴや図形では、色同士の相対関係の変化を見つけやすくなります。

1. グラフィックを含むクリップに別のLook用ノードを作ります。
2. RGB Mixerの一つの調整を変え、赤・緑・青の図形がそれぞれどう変わるかを見ます。
3. 公式ページが紹介するチャンネル交換も試せますが、元のブランドカラーが維持される保証はありません。変更前と比較して採否を決めます。
4. 文字の読みやすさ、細い線の境界、白い部分の色づきも確認します。指定色を正確に保つ必要がある制作では、意図的な混合が適切か判断してください。

RGB Mixerはカラープロファイルや正確な色指定を代替する道具ではありません。結果の色が用途に合うかは別に評価します。

## よくある問題と切り分け

| 症状 | まず確認すること |
| --- | --- |
| 全画面が強く色かぶりする | どのチャンネルを変えたか、一度に複数を動かしていないか、基本補正とLookが混ざっていないか |
| 肌や白い物体が不自然に変わる | 調整量、全画面への影響、局所補正を分ける必要 |
| モノクロで空や葉の階調が失われる | 元の色成分の寄与、変更前の階調、Waveform |
| RGB Paradeが一致しない | 元の物体の色と照明、Lookの意図。波形の一致を目的化しない |
| 別ショットへコピーすると色が変わりすぎる | 素材の色成分、照明、Input変換、ノード順序 |
| 変化が見えない | 正しいノードを選んでいるか、ノードが有効か、モノクロ設定の有無 |

**RGB Mixerで直せる問題と、そもそもの入力色空間の設定問題を区別**してください。入力変換が誤っている状態を、チャンネル混合で見た目だけ近づけても安定した色管理にはなりません。
