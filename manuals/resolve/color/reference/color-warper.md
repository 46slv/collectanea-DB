# Color Warperで色相と彩度の関係を調整する

空のシアンを青へ寄せたいが、青い衣装や肌の色はなるべく維持したい。色相だけを条件にした補正では、彩度が異なる部分までまとめて変わることがあります。**Color Warper（カラーワーパー）**は、色相と彩度の関係を網目状のグリッドで見ながら、選択した色の範囲を移動させるColorページのパレットです。

Blackmagic Designの[公式Colorページ](https://www.blackmagicdesign.com/jp/products/davinciresolve/color)では、グリッドまたはViewerから色相や範囲を選び、別の色相・彩度の位置へドラッグする方法が説明されています。輝度（明るさ）に基づいて色をワープする用途も案内されています。ここで扱うのは**Colorページのパレット**であり、Fusionの色処理ノードやResolve FXのワープエフェクトとは別です。

## Color Warperとほかの補正の違い

通常のHue vs Hueカーブは、色相を基準に別の色相へ動かすときに適しています。Color Warperでは色相と彩度を二次元の関係として扱うため、「鮮やかなシアンを深い青へ寄せ、低彩度の青灰色への影響を抑えたい」といった方向を試せます。ただし、**ほかの色が変化しない保証はありません**。変形に関係する範囲と実際の画素の色分布によって結果は変わります。

| 主な目的 | 候補 | 判断の基準 |
| --- | --- | --- |
| 露出や全体の色かぶりを整える | [Primaries](./primaries-color-wheels) | まず全画面の基本補正が必要か |
| 色相を条件にして色相・彩度を調整する | [HSL Curves](./hsl-curves) | カーブで調整の方向を把握しやすいか |
| **色相と彩度の位置関係を一緒に変える** | Color Warper | グリッドから対象の領域を選んで動かしたいか |
| 特定物体や位置への影響を限定する | [HSL Qualifier](./hsl-qualifier)／[Power Windows](./power-windows) | 色だけでは対象を十分に分離できないか |

Color Warperのグリッドは色の選択・編集のための表示です。**画素数の厳密なヒストグラムやScopesの代替ではありません**。色の変化はViewerと[Scopes](./scopes)で比較します。類似した色の物体が二つある場合、Color Warperが物体の意味を自動で区別することは期待しません。

## 操作前に確認すること

1. Colorページで対象ショットを選び、[カラーマネージメント](../learn/color-management-basics)のInput／Timeline／Outputの扱いを確認します。入力変換の誤りを色のワープで隠しても、安定した補正にはなりません。
2. [Node Graph](../learn/color-node-graph)で基本補正と別にColor Warperを使うシリアルノードを設けます。露出・ホワイトバランスとLookの責任を分けるためです。
3. Viewerで**変えたい色**と**維持したい色**の両方を決めます。たとえば空のシアンと衣装の青、ステージ衣装の赤と人物の唇です。
4. 調整前の画像を必要に応じて[Gallery／Stills](./gallery-stills)へ保存し、Vectorscopeでおおまかな色の分布を確認します。肌や雲の明暗が重要ならWaveformも見ます。

これらは作業上の推奨順であり、Resolveの固定操作順や内部の演算順を表すものではありません。

## 基本操作：色の領域を選んで移動する

1. Colorページで目的のノードを選び、**Color Warperパレット**を開きます。公式資料によれば、色相と彩度を扱う網目状グリッドが表示されます。
2. グリッドから調整したい色相または範囲を選びます。Viewerで被写体の色を見ながら選びたい場合は、公式ページで説明されている**Viewerからの選択**を利用します。
3. 選んだ領域を別の色相・彩度の位置へ**小さくドラッグ**し、変化を観察します。大きく動かすほど良い結果になるわけではありません。
4. Viewerで対象物だけでなく、似た色の衣装、肌、影、反射、ハイライトも確認します。Vectorscopeでも変更の傾向を見ます。
5. ノードを有効・無効にして変更前後を比較します。意図しない変化が目立つ場合は移動量や対象の選択を見直します。静止フレームだけでなく、動きがある区間も再生します。

この操作で裏付けが取れているのは、**グリッド／Viewerからの色選択、ドラッグによる色相・彩度の変更、輝度を基準とした調整機能の存在**です。21.1固有の細かいボタン名、グリッド分割数、範囲の広げ方、ショートカット、初期値は未照合です。操作画面で確認できない項目を想定で追加しないでください。

## 例1：シアン寄りの空を落ち着いた青へ

屋外のショットで、空がシアン寄りに見える一方、人物の青い衣装はそのまま維持したいとします。

1. Primariesで露出とホワイトバランスを整えます。白い壁まで青い場合は、色ワープの前に全体の色の問題を疑います。
2. Color Warperで空のシアン付近をViewerから選び、青寄りの位置へ少しずつ動かします。色相と同時に彩度が強くなり過ぎないようにします。
3. 雲やガラスの反射、人物の衣装も確認します。空の色が好ましくても、雲まで不自然な青に変わるなら成功とは判断しません。
4. 衣装も大きく変わる場合、色だけで分ける方式の限界を考え、[Power Window](./power-windows)で空の位置を限定する方法を検討します。
5. 動きのあるフレームや隣のカットを再生し、空が不連続に見えないか確認します。

**採否の例：** 空の色は狙いどおりだが、建物のガラスだけ不自然に青くなる場合、Color Warperの変形量を弱めるか、補正を適用する領域を限定します。特定のメッシュ移動量を固定プリセットとして示すことはできません。

## 例2：赤い衣装の主張を弱めて肌を残す

赤いステージ衣装の彩度が強く、顔から視線を奪ってしまうショットを想定します。Color Warperで衣装に近い色相・彩度の領域を選び、彩度を抑える方向を試します。

調整後は衣装だけでなく、**唇や頬の赤み**が失われていないかを確認します。赤に近い肌成分も灰色に近づくなら、色相と彩度の位置だけでは分離が足りない可能性があります。その場合は[HSL Qualifier](./hsl-qualifier)で選択範囲を確認し、必要に応じてWindowで場所も限定します。

**採否の例：** 衣装は落ち着いたが唇の血色まで弱くなった場合、衣装側だけを別の範囲として扱う方法へ切り替えます。画像中の物体を意味的に識別できるわけではないため、色が近い対象への波及は常に確認対象です。

## 輝度に基づく色のワープ

公式Colorページには、**輝度（明るさ）に応じて色をワープする**機能も記載されています。たとえば照明を受ける衣装の明るい部分と暗い部分の色の印象を分けて調整したい場合、輝度に基づく方法も検討できます。

ただし、21.1でのモードの正式な選択肢名、切り替え操作、グリッド軸、パラメータの範囲は直接確認できていません。ここでは存在が確認できる用途に説明を限定します。**輝度が違っても別の物体と値が重なる場合、位置や物体の分離は別途必要**です。

## うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| 空と一緒に衣装の色まで変わる | 同じ色域の物体への波及。Windowによる位置の限定 |
| 色相は合ったが彩度が強すぎる | グリッドでの移動方向と量、Vectorscope上の変化 |
| 肌や唇が不自然にくすむ | 赤や橙の共通領域への影響。Qualifierとの使い分け |
| 狙った対象が変わらない | 選択範囲、使用中のノード、そのノードの有効状態 |
| グラデーションの境界が不自然になる | 変更幅を小さくして再評価、周辺色の変化 |
| 別ショットへコピーすると印象が違う | 素材の色分布、照明、Input変換、ノードの位置 |
| 変形するほど全体が不自然になる | Primariesでの基本補正、入力色管理、HSL Curvesとの使い分け |

単一フレームで狙った色になっても、動きのあるカットや前後のショットで問題が出る場合があります。色の変更量だけでなく、**補正すべき領域と別の物体への影響**をセットで判断します。
