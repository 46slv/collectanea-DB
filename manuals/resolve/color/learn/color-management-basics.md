# カラーマネージメントの基礎（Input／Timeline／Output）

同じLog素材でも、プロジェクトのカラー管理が異なるとColorページに表示されるコントラストや彩度は変わります。グレーディングを始める前に確認したいのは、**カメラの信号をどのように解釈し、どの色空間で補正し、何を表示・納品するために変換するか**です。

DaVinci Resolveには、プロジェクトを通して変換を管理する**Resolve Color Management（RCM）**と、ノードへ**Color Space Transform（CST）**を置いて明示的に変換を組む方法があります。どちらも色変換を扱いますが、変換を置く場所と管理単位が違います。

## Input／Timeline／Outputを分けて考える

基本的な信号の流れは次のように考えると整理しやすくなります。

```text
撮影素材
  └─ Input：素材の色域と階調符号化を正しく解釈・変換
       └─ Timeline：作業用の色空間でショットを補正
            └─ Output：表示・納品先へ向けて変換
                 └─ モニター／書き出し
```

これは**概念上の流れ**です。実際のノード・グループ・出力処理の順序はプロジェクトのモードや設定で変わり、あらゆるモードで3個のノードが並ぶという意味ではありません。

| 段階 | 問うこと | 誤りに気付くための観察 |
| --- | --- | --- |
| Input | 入ってきた画像はどの色域・ガンマ／Logで記録されたか | 他のカメラと極端に異なるコントラストや彩度にならないか |
| Timeline | 補正操作へ渡す画像はどの作業空間か | 異なる素材でもグレーディングを一貫して進められるか |
| Output | 最終的にどの表示・納品条件へ変換するか | 対象の表示環境で階調や色が意図どおりか |

「Rec.709」「Log」といった名前だけでは変換条件が完成しません。少なくとも**色域（RGB primaries）と伝達特性（gamma／Logなど）**を区別します。たとえばLog素材をすでにRec.709へ変換したファイルは、元のカメラのLogデータと同じInputとして扱えません。

## RCM：プロジェクト側で変換を管理する

Blackmagic Design公式Colorページは、Project Settingsの**Color Management**でカラーサイエンス、Input／Timeline／Outputの変換、トーンマッピング等を設定できると説明しています。DaVinci YRGB Color Managed（RCM）では、素材の入力解釈と作業空間、納品先をプロジェクト側で整理する考え方を取ります。

異なるカメラが混在する案件では、素材ごとに正しいInputを識別したうえで同じ作業空間へそろえ、共通のOutputへ向けて確認できます。クリップの撮影設定が不明なら、メタデータだけで判断を確定せず、撮影記録や制作側の情報を確かめます。

### RCMを使うときの確認順

1. **納品先を決める。** SDRなのかHDRなのか、対象の表示条件と要求仕様を先に確認します。特定のOutputプリセットを素材によらない「正解」として選びません。
2. **Project Settings → Color Managementを開く。** カラーマネージメントを使うか、現在どのカラーサイエンスになっているかを確認します。
3. **素材のInputを確認する。** カメラ名だけでなく、撮影モード、色域、Log／ガンマ、すでに変換済みかを区別します。自動認識された値も無条件には信用しません。
4. **Timelineの作業空間を確認する。** 何の色域・階調符号化の画像をColorページで補正するかを明確にします。DaVinci Wide GamutとDaVinci Intermediateは、前者が色域、後者が符号化を表す別の要素です。
5. **Outputを設定し、ViewerとScopesで観察する。** 設定変更がクリップの見え方へ及ぼす影響を調べます。最後は対象のモニターと書き出し結果でも確認します。

RCMを有効にしたからといって、素材のInputが自動的に正しく特定されるとは限りません。また、Viewerの見た目だけではモニター校正や再生アプリ側の色管理の問題まで確定できません。

## CST：ノード上で変換の境界を明示する

**Color Space Transform**は、補正ノード上で入力側と出力側の色域・ガンマを指定して変換を設計するための効果です。Blackmagic Designの公式『The Colorist Guide to DaVinci Resolve 20』では、入力用CSTと出力用CSTの間をグレーディングの作業空間にする構成が紹介されています。

手動で変換を構成する場合の例は、次のようになります。

```text
[入力CST：カメラ素材 → 作業空間]
          ↓
[補正ノード：露出感・色・Look]
          ↓
[出力CST：作業空間 → 納品先]
```

この形は**DaVinci YRGBを使ってノード側で変換を管理する例**です。RCMのプロジェクトに同じ入力変換・出力変換を何も考えず重ねるための手順ではありません。入力CSTの出力と、次のノードが想定する作業空間が一致すること、出力CSTの入力も直前の作業空間と一致することを確認します。

CSTには色域変換とガンマ変換のほか、トーン／色域マッピングに関する設定があります。ただし、**どのマッピング方法・数値を選ぶかは素材と納品条件によります**。旧版のガイドにある画面やプリセットを、21.1の全モードで同一と断定しません。

### RCMと手動CSTの選び分け

| 判断軸 | RCM | 手動CST |
| --- | --- | --- |
| 管理する単位 | プロジェクト設定と素材ごとのInput割り当てが中心 | ノードごとの変換を目で追える |
| 複数カメラ | Inputが適切なら共通作業空間へ整理しやすい | 素材・ノードごとに変換の整合を管理する |
| 変換の変更 | プロジェクトのOutputや処理設定との関係を確認する | 対象ノードの前後と順序を確認する |
| よくある失敗 | Inputの誤認識・誤割り当て | 変換の二重適用、入出力の取り違え |

両者の併用がすべて禁止という意味ではありません。意図的に異なる色空間へ処理を移すCSTもあり得ます。ただし、**何の信号をどこからどこへ変換しているのか説明できないCSTを追加しない**ことが基本です。

## 判断例1：Log素材と通常のRec.709素材が混在する

インタビューをLogで撮り、資料映像はすでに表示用Rec.709として書き出されている案件を想定します。ここではRCMを使う場合の確認を示します。

1. 各素材の撮影・書き出し情報を確認し、**Logのカメラ原本**と**表示用に変換済みの映像**を区別します。
2. RCMのプロジェクトで、それぞれに対応するInput解釈を確認します。表示用映像へ撮影時のLog Inputを誤って割り当てないようにします。
3. 共通の作業空間で、それぞれの人物の肌や背景の明るさを[Scopes](../reference/scopes)でも比較します。
4. 全体補正と演出Lookを分けて調整し、ショットを交互に見て切り替わりの違和感を確認します。
5. 納品先へ向けたOutputを確認し、書き出したファイルを対象環境で検証します。

この例の完了条件は、**両素材に適切なInput解釈が与えられ、共通の出力条件でショット間の差を評価できること**です。「両方が同じ数値のRGBになること」ではありません。

## 判断例2：手動CSTで一部分だけ色が不自然になる

入力CST→補正→出力CSTという構成で、肌色だけが過剰に鮮やかになったとします。原因をCSTの「強さ」と決めつけず、次の順に切り分けます。

1. ソースが本当に指定したカメラ色域・Log／ガンマであるかを確認します。すでに正規化された素材を再変換していないかを見ます。
2. 入力CSTの**Output**と、後段が想定する作業空間を照合します。出力CSTの**Input**も同じ観点で確認します。
3. 変換以外の補正ノードを一時的に外し、不自然さがどこで生まれるか比較します。
4. クリップ・グループ・プロジェクト側の別の変換やLUTを確認し、同じ役割の変換が重複していないかを調べます。
5. トーンマッピングや色域マッピングが必要な素材・出力条件なのか、設定変更前後の階調と色を比較します。

CSTの出力が適切でも、その後の強い彩度補正が原因となることはあります。変換の誤りと通常のグレーディングの問題を分けて確認します。

## 困ったときの切り分け

| 症状 | 先に確かめること | 判断の方向 |
| --- | --- | --- |
| Log素材が極端に眠い／強すぎる | Inputの色域・ガンマ、既存LUT／CST | 変換不足か二重変換かを分ける |
| 一部のカメラだけ色が異なる | 撮影モード、Input割り当て | 同じInputを全素材へ機械的に適用しない |
| Outputを変えたらハイライトが大きく変わる | 出力条件、トーンマッピング、Viewerの表示経路 | 単純なRGB変換だけでない要因を調べる |
| Resolve内と書き出しの見え方が異なる | 出力変換、ファイルのタグ、再生アプリ、モニター | Colorページのノードだけを原因と断定しない |
| CSTを追加したら彩度・コントラストが崩れる | 既存RCM、入力データの状態、ノード前後 | 変換の重複と向きの誤りを確認する |

カラー管理の問題を調べるときは、[最初のグレーディング](./first-grade)と[ColorページのNode Graph](./color-node-graph)も参照してください。ViewerとScopesの読み方は[Scopes](../reference/scopes)、補正方法は[Primaries](../reference/primaries-color-wheels)を参照します。
