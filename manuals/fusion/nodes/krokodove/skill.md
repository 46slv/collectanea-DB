# sKill

**sKill**は、図形を構成する線分のうち、**指定した条件に当てはまる部分を取り除く**KrokodoveのShapeツールです。DaVinci Resolve 21.1 Reference Manualでは、Shapeの一部の線分を条件に従って除去するツールとして紹介されています。

ここでいう<Term id="shape-data">Shape</Term>は、円や四角形などの形を、まだ画像のピクセルへ変換せずに扱う**図形データ**です。sKillは映像の画素を消すフィルターではなく、Shapeを加工する段階に置きます。Shapeと通常の画像の違いは[シェイプ（Shape）](../../learn/02-data/shape)で説明しています。

## 「線分を取り除く」とは

四角形の輪郭を思い浮かべると、上・下・左・右の辺をたどって一周できます。輪郭の一部が欠ければ、つながって見えていた線に切れ目が生まれます。sKillの役割を理解するには、**完成した図形全体ではなく、その図形を構成する一部分を対象にする**と考えると分かりやすくなります。

ただし、この四角形は考え方の説明です。**sKillに「上辺だけを削除」という設定があることや、一辺を内部で必ず一つの線分として扱うことを示していません。** 曲線をどこで線分に区切るか、複数の輪郭をどう判定するかも公式Manualの記述からは確定できません。

重要なのは、**どの線分を除くかは条件で決まる**という点です。Manualはその条件をInspectorのコントロールで指定すると説明していますが、条件の種類や正式な項目名は列挙していません。長さ・角度・順番・位置などで選べると決めつけず、実機のInspectorで確かめる必要があります。

## 入力と出力

| 段階 | データ | 役割 |
| --- | --- | --- |
| 入力 | Shape | 前段で作った図形と、その輪郭を受け取る。 |
| 処理 | 条件に一致する線分の除去 | 図形を構成する部分のうち、指定条件に合うものを取り除く。 |
| 出力 | Shape | 後続のShape加工や[sRender](../shapes/s-render)へ渡す。 |

**Shape入力・Shape出力**という整理は、COLLECTANEAの既存ノードカタログと、21.1 Manualの「Shape Tools」という分類に基づきます。公式のsKill説明には、コネクターの正式名称、端子数、補助入力の有無は示されていません。

Shapeは通常の2D画像と異なるため、画像の合成やGlowなどへ進むときは、[sRender](../shapes/s-render)でピクセル画像へ変換します。線分を取り除く段階と、画像として表示する段階を分ける構成です。

## 主な設定項目と確認の考え方

21.1 Manualで確認できるのは、**「コントロールで指定した条件に合う線分を除く」**という機能です。特定のスライダー名、判定の方向、削除量の単位、初期値、アニメーション可能な項目は、ここからは分かりません。

実機でInspectorを開いたら、まず「どの項目が線分の選別に関係するか」を調べます。ある値を変えたときに、どこが残り、どこが消えたかを観察します。結果が変化したからといって、その値が必ず線分の長さや番号を表すとは限りません。

## 最小構成と確認手順

次は**実機確認用に考えた構成案**です。21.1実機での接続や設定値、出力結果を検証済みという意味ではありません。

```text
sRectangle → sKill → sRender → MediaOut
   四角形      線分を除く    画像化      表示
```

1. [sRectangle](../shapes/srectangle)を[sRender](../shapes/s-render)へ直接接続し、まず図形が表示できることを確認します。輪郭が見やすい表示状態を選びます。
2. sRectangleとsRenderの間へsKillを挿入し、Shapeの接続が成立するか調べます。
3. sKillのInspectorを開き、実際に存在する条件の項目を確認します。**資料にない項目名や数値を探す前提にはしません。**
4. 条件に関係する項目を一つだけ変え、元の図形と見比べます。どの部分が消えたか、輪郭が途切れるか、塗りの見え方も変わるかを確認します。
5. 変化が読み取りにくい場合は、[sPolygon](../shapes/spolygon)で辺の長さや角の数が異なる形を作り、同じ条件で比較します。sRenderの解像度とViewer倍率は固定します。

**何も変わらない場合**は、いったんsKillを外して元のShapeが表示されているか確認します。そのうえで、選んだ条件に合う線分が実際にあるか、輪郭線と塗りのどちらを見ているかを分けて調べます。変化がないことだけでsKillの不具合とは断定しません。

## 主な用途

### 途切れた装飾枠を作る

タイトルを囲む図形の一部を欠かせたデザインを検討するときに候補になります。たとえば四角形の枠を作り、sKillで条件に一致する部分を除けるか調べます。ただし、**特定の角や一辺だけを自由に選んで消せる機能は未確認**です。狙った箇所へ正確な切れ目を配置したい場合は、最初から分割したShapeを作るなど、結果を直接制御できる方法も比較してください。

### 複数の線分を持つ図形の見え方を変える

[sPolygon](../shapes/spolygon)などで複数の辺からなる輪郭を作り、どの部分が残るかを確認する用途です。条件によって異なる見え方を作れれば、線の疎密や欠け方を利用したグラフィックに応用する余地があります。**残る線分の本数や配置を任意に設計できるという保証ではありません。**

### 別のShape加工と組み合わせる

輪郭の取り方を変える[sResample](./sresample)や、各線分を波打たせる[sZigZag](./szigzag)と組み合わせると、**どの段階の輪郭に対して条件を評価するか**を調べられます。

```text
sPolygon → sKill → sZigZag → sRender
sPolygon → sZigZag → sKill → sRender
```

これは処理順を比較するための案であり、両方の接続が成立することや、並べ替えると一定の差が出ることを確認したものではありません。単独の動作を確かめてから比較します。

## 似たノードとの違い

| ツール | 対象と役割 | sKillとの違い |
| --- | --- | --- |
| **sKill** | 条件に一致するShapeの線分を取り除く | 線分の選別と除去が目的。 |
| [sWriteOn](./swriteon) | 輪郭を描いて現す・隠す | 表示の進行を扱う。sKillに同じアニメーション機能があるとは限らない。 |
| [sResample](./sresample) | 輪郭のサンプリングを変える | 線分を削除する目的とは異なる。 |
| [sZigZag](./szigzag) | 各線分を波状に変形する | 残す線の形を変える処理で、条件除去とは別。 |
| [sRound](./sround) | 角を曲線にする | 角の形を変える。 |
| [sRestyle](./srestyle) | 塗りや輪郭線の外観を変える | 色や線の見た目を変えるのであり、線分を除くとは限らない。 |

**「見えなくする」と「線分を取り除く」は同じ仕様ではありません。** sWriteOnは輪郭を現す・隠すツールとして、sKillは条件に合う線分を除くツールとして公式Manualに別々に記載されています。sKillによる除去が内部データ上でどのように保持されるか、時間とともに元へ戻せるかまでは確認していません。

## 注意点と検証範囲

- **21.1 Manualで確認済み**：KrokodoveのShape Toolsに分類され、コントロールで指定した条件に合う線分を除去する機能。
- **既存カタログに基づく構成**：Shapeを入力・出力として扱い、2D画像化するときはsRenderを使用する。
- **未確認の条件指定**：Inspector項目の正式名称、選択可能な条件、値域、初期値、線分の判定単位と処理順序。
- **未確認の形状挙動**：開いた輪郭・閉じた輪郭、曲線、複数Shape、塗りつぶし、内部に交差線がある図形の扱い。
- **未確認の環境差**：実機の端子名と数、アニメーション、内部REGID、Resolve Free／Studio／Fusion Studioでの提供差。
