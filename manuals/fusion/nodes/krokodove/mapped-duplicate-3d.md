# Mapped Duplicate 3D

Mapped Duplicate 3Dは、**同じ3Dオブジェクトを縦・横・奥行き方向に並べ、コピーごとの変化を画像で制御する**Krokodoveツールです。たとえば小さな立方体を何列にも並べ、その一部だけ位置をずらしたり、向きや大きさを変えたりする表現を考えられます。

Manualがいう「3D grid」は、画面の上に格子線を描くという意味ではありません。3D空間に複製の配置先を格子状に設けることです。X方向には左右、Y方向には上下、Z方向には奥行きがあるため、平面のタイル配置とは異なり、複製が手前と奥にも分かれます。

たとえば横3列・縦2列・奥行き2層なら、**配置場所が3×2×2で12か所ある**状態を想像できます。これは仕組みを説明するための例で、Inspectorに同名の個数設定があることや、元のオブジェクトを数に含める方法を示したものではありません。

## 扱うデータと入力・出力

複製の対象は<Term id="classic-3d">Classic 3Dシーン</Term>のオブジェクトで、変化の制御には<Term id="image">2D画像</Term>を使います。この2つを区別することが重要です。

| 役割 | 何を渡すか | 結果にどう関わるか |
| --- | --- | --- |
| 複製する3Dオブジェクト | Cubeなどの3D形状や3Dシーン | 格子状に配置される対象になる |
| 制御用の画像 | 模様や明暗などを持つ2D画像 | 複製の位置・回転・拡大縮小・時間などの変化に利用できる |
| 出力 | 複製を含む3Dシーン | カメラ・ライトと組み合わせ、Renderer 3Dで2D画像へ描画する |

ここでいう画像は、オブジェクトの表面へ貼り付けるテクスチャとは役割が違います。画像の内容を**各コピーの変化を決めるための情報**として利用するのが、このツールの特徴です。

ただし、21.1 ManualのKrokodove一覧は機能の短い紹介です。**正確な端子名・入力数・必須接続、どの画素やチャンネルを各コピーが読むか、画像の値をどの設定量へ変換するか**までは書かれていません。上の表はデータの役割を示し、実機で確認した接続端子の一覧ではありません。

## 画像で何を変えられるか

21.1 Manualには、画像を使ってコピーの**offset、rotation、scale、timing**などを制御できると記載されています。

| 変化 | 見た目に起きることの例 | 注意点 |
| --- | --- | --- |
| 位置のずれ（offset） | まっすぐ並んだ立方体の一部が列から飛び出す | どの軸へどれだけ動くかを画像から決める具体式は未確認 |
| 回転（rotation） | 同じ向きだったカードや箱がそれぞれ違う方向を向く | 色チャンネルと回転軸の対応は未確認 |
| 拡大縮小（scale） | 一部のコピーだけ大きく、別のコピーは小さく見える | 明るい画素ほど大きくなるとは断定できない |
| 時間（timing） | アニメーションを持つ複製の変化をコピーごとにずらす用途が考えられる | 何の時刻を参照し、どうずらすかは実機での確認が必要 |

この表の見た目の例は**Manualの機能説明から考えた用途**です。特定の画像を接続すれば必ずこの結果になる、という実測結果ではありません。

## 運用例：立方体の配列に部分的な変化を付ける

まずは配置そのものと、画像による制御を分けて確認します。次の図は**信号の役割を示す概念図**で、画像用の正式な端子名や端子位置は示していません。

~~~text
Cube 3D（複製の対象） ────────────┐
                                  ├→ Mapped Duplicate 3D ──┐
2D画像（制御用マップ） ────────────┘                         │
Camera 3D ──────────────────────────────────────────────────┼→ Merge 3D
ライト（必要な場合） ──────────────────────────────────────┘
                                                                  ↓
                                                            Renderer 3D
                                                                  ↓
                                                               2D画像
~~~

1. [Cube 3D](../3d/cube-3d.md)などで、ひとつの簡単な立体を用意します。複製される形が分かりやすいよう、最初は複雑なモデルを使いません。
2. Mapped Duplicate 3Dで、XとYに複製が並ぶ状態を確認します。次に奥行き方向の配置も試し、2Dの行列ではなく3D空間に複製が存在することをViewerで確認します。配置数・間隔に対応する**正確なInspector項目名は未確認**なので、実機表示に従って設定します。
3. 制御用の画像を用意します。最初は一様な画像と、左右で内容が明確に違う画像を比較すると、画像による制御の有無を切り分けやすくなります。
4. 実機で確認できる画像入力と対応する設定を使い、**位置の変化だけ**を試します。回転・大きさ・時間は同時に動かさず、画像を変えたときにどのコピーがどう変化したかを見ます。
5. 位置の変化を確認できたら、回転・拡大縮小・時間の制御を**ひとつずつ**試します。画像のどこがどのコピーに対応するかは、結果を比べて確認します。
6. 複製結果を[Merge 3D](../3d/merge-3d.md)でCameraなどとまとめ、[Renderer 3D](../3d/renderer-3d.md)から2D画像として描画します。実写映像に重ねる場合は、描画後に通常の[Merge](../compositing/merge.md)へ渡します。

これは**実機で機能と対応関係を調べながら組み立てる手順**です。画像を接続する順序、画像の白黒と変化量の対応、コピー番号や格子座標の割り当て方式を推測していません。意図した違いが出ない場合は、制御画像だけを入れ替え、他の条件を固定して観察します。

### なぜRenderer 3Dが必要なのか

Mapped Duplicate 3Dの複製結果は、カメラを動かすと見え方が変わる**3Dの配置**です。これを通常の2D映像と合成するには、[Renderer 3D](../3d/renderer-3d.md)でカメラ視点の画素へ変換します。画面上で単に画像を何枚も並べる2D処理とは、ここが異なります。

## Duplicate 3D・Replicate 3Dとの選び分け

| Node | 配置を決める考え方 | 向いている例 |
| --- | --- | --- |
| **Mapped Duplicate 3D** | X・Y・Z方向の格子状配置と、画像による各コピーの変化 | 同じ箱を多数並べ、画像に応じて向きや大きさを変えたい |
| [Duplicate 3D](../3d/duplicate-3d.md) | コピーごとにTransformを加えて規則的に複製する。JitterやRegionなども備える | 一定間隔の列や円弧、螺旋状の複製を作りたい |
| [Replicate 3D](../3d/replicate-3d.md) | 別のMeshの頂点やParticleなどを複製先の位置として利用する | 球面の頂点へ小物を置きたい |

単に一定間隔で並べるなら、詳しいInspectorが21.1 Manualに記載されているDuplicate 3Dから始める方が設定を確認しやすい場合があります。**画像の情報に沿ってコピーごとの差を作りたい**ときにMapped Duplicate 3Dを比較します。Duplicate 3Dと同じCopies・Jitter・Region設定を持つとは限りません。

## 注意点と未確認事項

- **画像は3Dオブジェクトに自動変換されない**：画像は複製の変化を制御する側のデータです。複製元の3D形状とは別に考えます。
- **画素とコピーの対応は未確認**：画像の明暗・色・Alphaを、どの順序でどのコピーに適用するかはManualの短い説明から確定できません。
- **時間制御の詳細は未確認**：アニメーションの開始時刻・再生速度・位相など、何が変更されるかを特定していません。
- **複製数は描画負荷に関わる**：多数の立体がある構成では、最初は小さな格子で確認し、必要な数へ増やします。具体的な上限や最適化方法は未検証です。
- **正確なUI仕様は別途実機確認が必要**：REGID、各端子の名称・色と本数、Inspectorのラベル・初期値・値域、Free / Studioでの利用可否は確認していません。
