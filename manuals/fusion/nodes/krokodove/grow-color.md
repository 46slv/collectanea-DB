# Grow Color（Krokodove）

**Grow Color**は、画像の縁にある色を透明な部分へ伸ばして、その空いた領域を埋めるKrokodoveのツールです。たとえば、背景が透明なロゴの色を周囲へ広げたいときに候補になります。ロゴの輪郭を描き直すのではなく、**既存の画像にある色を使って透明な場所を補う**処理です。

DaVinci Resolve 21.1 Reference Manualでは、Krokodoveの「Image Tools」に分類されています。説明されているのは、画像の端の色を引き伸ばして透明部分を埋めるという役割までです。どこまで伸びるか、色の混ざり方、Inspectorの正式な設定名や透明度の処理は、Manualの記述だけでは確定できません。

## 何が変わるのか

ここでいう「透明な部分」は、絵が黒く塗られている場所とは異なります。<Term id="image">Image</Term>には色の情報に加えて透明度を表す情報があり、背景のないPNGやキーイングした素材には、色が見えている部分と、下の映像が透けて見える部分があります。

例として、透明なキャンバスの中央に青い四角形を置いた画像を考えます。

- **加工前：** 青い四角形だけが見え、周囲には画像の内容がないため、背後の映像が見える。
- **Grow Colorの役割：** 四角形の縁にある青い色を、周囲の透明領域へ延ばす。
- **確認したい加工後：** 青い領域がどの方向・どの距離まで広がったか、透明だった領域の見え方がどう変わったか。

単純な青い四角形なら、広がった場所は同じ青に見えると考えられます。一方、輪郭に複数の色がある画像では、どの色がどこへ延びるかによって結果が変わります。この二つは**効果を理解するための模式例**で、処理方向や色の優先順位を実機で測定した結果ではありません。

また、「色が伸びる」と「不透明な領域が同じだけ広がる」は同義ではありません。色（RGB）が付くことと透明度（Alpha）が変わることを分けて観察する必要があります。

## 入力と出力

| 段階 | 扱うもの | 意味 |
| --- | --- | --- |
| 入力 | 2D Image | 透明な部分と、そこへ伸ばす元になる色を含んだ画像。 |
| 処理 | 画像の縁の色を透明部分へ延長 | もともと見えていた画像の周辺へ色を広げる。 |
| 出力 | 2D Image | 変化後の画像をViewerで比較し、合成の後段へ渡す。 |

この分類は21.1 Manualの「Image Tools」と、既存のCOLLECTANEAノードカタログに基づきます。正式な端子名、端子数、追加のマスク入力があるかどうかは確認できていません。Shapeの輪郭データや3D Sceneを直接受け取るノードであるとは説明されていません。

**元画像に透明な部分がない場合**、Grow Colorが何をどう変更するかは資料だけでは分かりません。最初の検証には、透過PNGや透明なBackgroundの上に図形を描いた素材のように、透明部分が明確にある画像を使います。

## 主な用途

### 透明なロゴの周辺へ色を広げたい

背景を抜いたロゴやマークで、輪郭付近の色を外側へ広げる用途が考えられます。ただし、Grow Colorが輪郭から一定距離だけ広がるのか、画像の透明部分をすべて埋めるのかは未確認です。完成したロゴの縁や透明度を正確に保つ必要がある場合は、出力画像を拡大表示して確認します。

### 合成前に透明な隙間の扱いを調べたい

別の画像を重ねたとき、透明な部分に周囲の色を使いたい場合の比較候補になります。色が付いていてもAlphaが0のままなら、通常の合成では見えないことがあります。意図どおりの結果になったかは、単独のViewerだけでなく合成後にも確かめます。

### グラフィックの色を外へ引き延ばす表現を試したい

縁に色の変化がある小さな図柄から、周囲へ色がどのように広がるかを観察できます。これは応用案であり、色の広がり方を細かく指定できるという仕様確認ではありません。背景の延長を目的とする場合でも、元画像の模様まで自然に復元できるとは考えないでください。

## 最小構成：青い四角形で確かめる

次は**操作確認のために提案する接続例**です。21.1 Manualに掲載された専用の接続図ではありません。

~~~text
Background（透明なキャンバスに青い四角形を描いた画像）
    ↓
Grow Color
    ↓
MediaOut

加工前とGrow Colorの出力をそれぞれViewerで比較
~~~

1. 透明な部分が大きく残る画像を用意します。最初は青い四角形など、一色で輪郭が分かるものを使うと変化を追いやすくなります。図形の作成方法は任意で、ここではGrow Color自体の検証に集中します。
2. 画像をGrow Colorへ渡し、前段と後段の画像をViewerに表示します。**青色が増えた範囲**と**透明部分がどう見えるか**を別々に確認します。
3. Inspectorに実際に表示される項目を確認し、一度に一項目だけ変えて前後を比較します。この記事では存在を確認できない操作名・初期値・数値を指定しません。
4. Viewerにチェッカー状の透明表示がある場合は、見た目だけで不透明になったと判断せず、背景の異なる画像に重ねて比較します。
5. 一色の図形で変化をつかめたら、輪郭に赤と青の二色がある画像を試します。異なる色が隣り合う部分でどのような伸び方になるかを観察します。

合成確認のための構成案は次のとおりです。

~~~text
ロゴ画像 → Grow Color ─┐
                       Merge → MediaOut
別の背景画像 ─────────┘
~~~

Mergeでは加工したロゴを前景、別の画像を背景として重ねます。結果が見えない場合は、Grow Colorの効果が弱いと決めつけず、前景側のAlphaも確認してください。逆に透明な場所が完全に不透明になる場合は、意図せず背景を隠していないかを調べます。

## Extend・Grow・Clean Edgesとの違い

| ツール | Manualで確認できる働き | 最初に選ぶ場面 |
| --- | --- | --- |
| **Grow Color** | 画像の縁の色を伸ばして透明部分を埋める。 | **透明な領域**を周囲の色で補いたい。 |
| [Extend](./extend) | 画像端の画素を水平方向・垂直方向に複製し、反復した見た目を作る。 | **画像の外周**の画素を一方向へ繰り返したい。 |
| [Clean Edges](./clean-edges) | フレーム端の画素を複製するか単色で補う。 | 元画像の**四辺にある不要な線や画素**を処理したい。 |
| [Grow](./grow) | 一つ以上の開始位置から画像を成長・消失させる。 | 指定した位置を起点に画像が現れる・消える動きを検討したい。 |

Grow Colorの「画像の縁」が、常にキャンバスの四辺だけを指すとはManualに書かれていません。透明部分へ色を伸ばすという説明が重要です。一方、Extendの説明には水平方向・垂直方向の反復が明記されているため、二つを同一の処理として扱いません。

「透明部分を補いたい」のか「外周の画素を繰り返したい」のかを先に決めると、適切なノードを選びやすくなります。

## 挙動と注意点

- **透明度：** Manualは透明部分を埋めると説明しますが、RGBとAlphaの変更規則、最終的な不透明度までは示していません。合成結果で確認します。
- **色の境界：** 違う色が接する輪郭では、境界がどのように延びるかで縞や不連続が見える可能性があります。これは一般的な制作上の観察ポイントで、特定の補間アルゴリズムを示すものではありません。
- **解像度・範囲：** 出力画像のキャンバスが広がる、すべての透明部分が必ず埋まる、一定距離だけ伸びる、といった仕様は確認できていません。
- **画素の復元ではない：** 色を延ばすことは、透明部分の後ろに本来あった人物や背景の細部を復元することではありません。
- **バージョン差：** Inspectorの項目名・値域・初期値、内部REGID、Resolve Free / Studio / Fusion Studioでの違いは実機未確認です。

## 関連する考え方とノード

画像は色だけでなく透明度も持ちます。入出力を理解するには[画像データの解説](../../learn/02-data/image)と[Krokodoveファミリーの概要](./)を参照してください。
