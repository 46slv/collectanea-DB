# Anaglyph

Anaglyph [ANA]は、左眼用と右眼用の2枚の画像を**赤／シアンなどの異なる色に振り分け、1枚の画像に合成する**Nodeです。対応する色付き眼鏡で見ると、左右の眼に別々の像が届くため、元画像に左右の視差があれば立体として見えます。

たとえば、少し異なる位置から撮った左右2枚の映像を入力すると、赤とシアンがずれて見える1枚の画像を作れます。裸眼では輪郭に色ずれが見えますが、赤／シアン眼鏡を通すとそれぞれの眼に異なる像が届きます。Anaglyph自体が奥行きを計算したり、平面の画像から右眼用の映像を生成したりするわけではありません。

**DaVinci Resolve Studio / Fusion Studio限定のNode**です。無償版DaVinci Resolveで同じNodeが利用できるとは扱わないでください。

## 役割と出力

このNodeの仕事は、ステレオ制作で用意した**左眼・右眼の2D Imageを、色付き眼鏡で表示できる1枚の2D Imageへ変換すること**です。主に制作の終盤で、立体視のプレビューやアナグリフ形式の確認・出力に使います。

出力は赤／シアンなどの色情報を含む**通常の2D画像**です。左眼・右眼の2枚が別々に出力されるわけでも、視差（Disparity）や奥行き（Z Depth）のデータが出るわけでもありません。画像データの意味については[画像（Image）](../../learn/02-data/image.md)も参照してください。

## 入力

| 端子 | 入れるもの | 役割 |
| --- | --- | --- |
| **Left Eye**（オレンジ） | 左眼用の2D Image | 左眼の視点から見た画像。左右を1枚に並べた画像を使う場合も、ここへ接続します。 |
| **Right Eye**（緑） | 右眼用の2D Image | 左右が別々の画像の場合、右眼用を接続します。 |
| **Effect Mask**（青） | Mask | アナグリフへの変換を画面の一部へ制限します。 |

左右が**別々の画像**ならLeft EyeとRight Eyeの両方を使います。左右があらかじめ**横並び・縦並びで1枚に収められた画像**なら、オレンジのLeft Eyeへその1枚だけを入れ、後述のHoriz StackまたはVert Stackを選びます。別画像方式と1枚に並べた方式では、入力の仕方が異なります。

Effect Maskは任意です。たとえばRectangleのMaskを接続すると、画面の指定領域だけにアナグリフ変換を適用できます。Maskの範囲外の画素が最終的にどのように見えるかは、設定と接続した素材でViewer確認してください。

## 最小構成

まず、左右別々の静止画または映像を使う構成です。

~~~text
左眼の画像 ── Left Eye（オレンジ）──┐
                                    ├── Anaglyph ── MediaOut / Viewer
右眼の画像 ── Right Eye（緑）───────┘
~~~

1. 同じ場面を左右の視点から見た2枚の画像を用意します。別の場面や時間の異なる画像を使っても、自然な立体視にはなりません。
2. 左眼の画像をオレンジ、右眼の画像を緑の入力へ接続します。
3. Inspectorの**Color Type**で手元の眼鏡に合う色の組み合わせを選びます。一般的な赤／シアン眼鏡ならRed/Cyanです。
4. **Method**を切り替え、色の残り方、明るさ、像の二重写りをViewerで比較します。
5. 眼鏡で見たとき奥行きが逆転して見える場合は、入力の左右と**Swap Eyes**を確認します。

この接続例はManualに示された基本構成に沿っています。最終納品が左右2映像やSide-by-Side形式を要求する場合、Anaglyphはそれらの納品形式そのものを作るNodeではありません。

## Inspectorの主な設定

### Color Type：眼鏡の色を選ぶ

左右の画像を、どの色チャンネルの組み合わせへ割り振るかを選びます。

| 選択肢 | 対応する色分離 |
| --- | --- |
| **Red/Cyan** | 赤／シアン。一般的なアナグリフ眼鏡で使う方式。 |
| **Red/Green** | 赤／緑。 |
| **Red/Blue** | 赤／青。 |
| **Amber/Blue** | 琥珀色／青。 |
| **Green/Magenta** | 緑／マゼンタ。 |

**眼鏡とColor Typeを一致させることが前提**です。色の組み合わせが違うと、左右の眼に渡す像を十分に分離できません。色の方式だけで表示装置や眼鏡の特性が自動補正されるわけではありません。

### Method：色の残し方を選ぶ

同じRed/Cyanでも、左眼・右眼の色情報をどう使うかによって、明るさ、元の色の再現性、立体視の見やすさが変わります。

| Method | 何をするか | 選択の目安 |
| --- | --- | --- |
| **Monochrome** | 左右の画像を明るさの情報として扱い、それぞれの色チャンネルに割り当てる。 | 元の色より形や奥行きの確認を優先するとき。 |
| **Half-color** | Red/Cyanの例では、左眼の明るさを赤へ、右眼の色成分を緑・青へ割り当てる。 | 一部の色を残しつつ、見やすさとのバランスを探すとき。 |
| **Color** | 左右の画像から、それぞれの眼鏡の色に対応するチャンネルを使用する。 | 元のカラー情報をなるべく残したいとき。ただし強い色で左右差が目立つ場合がある。 |
| **Optimized** | Red/Cyanの例では、左眼画像の緑・青成分から赤出力を作るなど、左右の明るさの偏りを減らす。 | 左右の眼で見える明るさが大きく異なるとき。 |
| **Dubois** | 赤／シアン眼鏡の分光特性を考慮した色変換を行い、左右の干渉や色差の負担を減らすことを狙う。 | 赤／シアンで、色の強い素材や二重写りを比較したいとき。 |

表の色チャンネルの例は**Red/Cyanを前提**にしたものです。ほかのColor Typeへ同じ割り当てがそのまま適用されるとは限りません。

**Optimized**は、赤／シアン眼鏡で左右の明るさに差が出やすいことを考慮した方法です。Manualでは、左眼の緑・青を使って赤チャンネルを構成する例が示されています。元の赤成分を忠実に復元する方法ではなく、両眼で見やすい表示を優先する選択肢です。

**DuboisはRed/Cyan専用**です。Manualが説明する変換行列は赤／シアン眼鏡とCRT（Trinitron）の発光特性を前提にしているため、現在のLCD等で必ず最良の結果になるわけではありません。二重写り（片眼の像がもう一方にも見える現象）の少なさは、実際の眼鏡とモニターの組み合わせでも確認します。

### Swap Eyes：左右を入れ替える

左右の眼へ割り当てる入力を交換します。奥行きが手前・奥で逆に見える、左右の素材を逆に接続した疑いがある、といった場合の確認に使えます。

これは**カメラ位置や被写体の位置を動かす設定ではありません**。素材自体の左右のずれや時間ずれを修正する機能でもありません。

### Horiz Stack：左右が横並びの1枚を使う

左右の像が横に並んだ画像を、**オレンジの入力1本**から受け取ります。元画像の**左半分を左眼、右半分を右眼**として使い、Anaglyph出力は**元画像の半分の幅**になります。

たとえば1920×1080の左右画像を横に2枚並べた3840×1080の入力なら、出力の画像サイズは1920×1080です。この寸法例はManualの半幅ルールからの計算例で、実機での出力検証値ではありません。

### Vert Stack：左右が縦並びの1枚を使う

左右の像が縦に並んだ画像を、**オレンジの入力1本**から受け取ります。Manualの規則では、**下半分が左眼、上半分が右眼**です。出力の画像サイズは**元画像の半分の高さ**になります。

たとえば1920×2160の入力なら、出力サイズは1920×1080になります。上側を左眼として並べている素材では、意図と左右が逆になるので、**Swap Eyes**または素材側の並びを確認します。

Horiz StackとVert Stackを使うのは、**左右の眼の画像がすでに1枚に並んでいる場合**です。通常の1枚の映像にチェックを入れても、新しい右眼像が自動生成されるわけではありません。

### Settingsタブ

Settingsは他のStereo Nodeとも共通の設定群です。Anaglyph固有の色分離を調整する中心項目はControlsタブ側にあります。共通項目の初期値・範囲については、ここでは実機未確認の数値を追加しません。

## 運用例

### 立体視CGを赤／シアン眼鏡で確認する

3Dシーンから左眼と右眼のレンダリングを別々に出し、Anaglyphの2入力へ接続します。**Color Type: Red/Cyan**を選んで、眼鏡をかけて物体の前後関係を確認します。MethodをMonochromeからHalf-color、Optimized、Duboisなどへ切り替えると、色の見え方と左右の像の分離の違いを比較できます。

この方法は最終的なStereo映像の**確認用表示**として便利です。ただし、視差そのものの大きさ、画面端の不一致、左右の画の同期などは前段で確認する必要があります。

### Side-by-Side素材を1枚のアナグリフ画像へ変える

左右眼の像を横に並べた素材をLeft Eyeへ接続し、**Horiz Stack**を使います。通常の左右別画像のようにRight Eyeへもう1本つなぐ必要はありません。

Vertical Stack素材なら**Vert Stack**を使います。上下のどちらが左眼かが決まっていない素材では、まずそれを確認してください。ManualのVert Stackでは下半分が左眼です。

### 画面の一部で合成結果を比較する

Left EyeとRight Eyeを接続した状態で、青いEffect MaskにRectangleなどのMaskをつなぎます。マスクの領域に変換を限定することで、ステレオ合成の効果を部分的に確認できます。境界での見え方やMaskの混合結果は、実際の画像で確認します。

## 間違えやすい点と関連Node

- **左右に視差がない**：Anaglyphは色チャンネルを分けるだけです。同じ画像を左右に入れても、意味のある立体視差は新たに生まれません。
- **色の輪郭が二重に見える**：眼鏡なしでは色分離が見えるのは正常です。眼鏡を使っても大きく二重に見えるときは、左右画像の位置合わせ、視差量、色分離方式、表示環境を切り分けます。
- **左右が逆に感じる**：入力端子、上下／左右の並べ方、Swap Eyesを確認します。
- **[Stereo Mix](../materials-lights/stereo-mix.md)との違い**：Stereo Mixは3Dオブジェクトの左右眼用**Material**を決めるNodeです。Anaglyphはレンダリング後などの左右の**2D画像を色分離して合成**します。
- **[Combiner](./combiner.md) / [Splitter](./splitter.md)との違い**：左右像を所定の形式へまとめたり分離したりするのと、色付き眼鏡用に色チャンネルへ振り分けるAnaglyphは目的が異なります。必要な最終表示形式を先に決めます。
- Stereo系の全体像は[Stereo 3Dノード](./index.md)を参照してください。
