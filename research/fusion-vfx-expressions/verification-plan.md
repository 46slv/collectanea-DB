# 映像VFX表現の実機検証計画

[定番VFX表現73件の索引](./index) を、後で一つずつ試すための手順と記録項目です。**現在は未着手の検証計画**であり、再現・性能・Free/Studio差を確認したという記録ではありません。

## 目的と完了条件

- 完成映像の説明と、実際に得られた映像が対応する。
- 最小Node Graphと主要パラメータが確認され、最初から同じ操作を再実行できる。
- **公式仕様で確認済み／実機で観測／構成上の推測**の境界がページから分かる。
- Fusion標準で難しい場合、既存のResolve FX（OFX）、Blender、外部処理を使う理由と境界が分かる。
- 成功・制限・失敗を隠さず、読者向けの[Recipes](https://46slv.github.io/collectanea-DB/manuals/fusion/recipes/)へ必要なものを昇格させる。

## 1候補ごとに記録する項目

| 項目 | 記録すること |
| --- | --- |
| ID・成果イメージ | 索引のID、必要なBefore/After、用途 |
| 素材・環境 | Resolveの正確なversion/edition、OS、クリップ条件、解像度、fps |
| 出典 | Manualの章・ページ、使用した公式資料、参考記事のURLと確認日 |
| 最小Graph | 実際に接続したNode、データの種類、主要設定、レンダーの出力先 |
| 変化させた値 | 実際に見たパラメータ名と少なくとも1種類の調整前後 |
| 結果 | 静止画像/短尺レンダー、狙った表現と実際の差、再現手順 |
| 負荷 | 使用GPU/VRAM、処理時間または再生状況（測定できたときだけ） |
| トラブル | Frame jump、Alpha、DoD、位置ずれ、処理負荷、Free/Studio差 |
| 判定 | 下記の状態、確認した日時、対象commit/ページ |

実機画像がある場合は自分で作成した素材・Graph・Inspectorの画面を優先し、他サイトの画像を無断転載しません。

## 検証状態を混ぜない

1. **候補** — 見た目の名前と初期構成案を収集しただけ。
2. **資料確認** — 21.1 Manualや公式情報で、必要なNode/機能を確認した。まだ再現していない。
3. **実機で再現** — 固定入力でNode Graphの結果を確認し、途中フレームやレンダリングも再実行できた。
4. **Recipe公開** — 読者が操作できる手順、失敗時の確認、画像/動画、関連Node、制約を整備した。
5. **制限あり／不可** — 必要条件で実現できない、外部処理が必要、結果が不安定などを**根拠付き**で示した。

「資料確認」だけを「実機で再現」へ昇格しません。ユーザーに教えるには、最低限の実機レンダーと出典照合を別に確認します。

## 比較用の共通素材（後で準備）

- **S1: 透過文字・ロゴ** — 1920×1080のText+/PNG。形とAlphaの変化を見る。
- **S2: 移動人物** — 明るさ・背景が比較的安定した短いクリップ。Magic Maskや追従を確認する。
- **S3: 風景とカメラ移動** — 平面トラッキング、Camera Tracker、奥行き・遮蔽の確認用。
- **S4: 明暗差・高輝度・細線** — グロー、色収差、グリッチ、光学系の比較用。
- **S5: 3D幾何／破片** — 物理・材質系がFusion単独と外部連携でどう違うか確認する。

数字は**テスト設計値の提案**であり、すでに作成した素材や検証実績を示しません。

## 進める順番

**第1群: 基礎を使い回しやすいもの** — `D-01`、`D-02`、`T-01`、`T-03`、`X-01`、`M-01`、`L-06`。Image/Mask/Particles/Timeの境界を先に安定させます。

**第2群: 実写とTracking** — `C-01`、`C-03`、`C-05`、`C-07`。切り抜き、動き、背景復元を確認します。

**第3群: 特殊アルゴリズムと物理** — `L-04` ピクセルソート、`L-05` データモッシュ、`R-01` 破砕、`R-03` 流体など。通常のノード合成で近似するのか、外部ツールで処理するのかを比較します。

一括で73件に実機検証済みの印を付けないでください。**1件ごとに資料確認 → 最小実験 → 結果の確認 → 公開用Recipe**の順に記録します。
