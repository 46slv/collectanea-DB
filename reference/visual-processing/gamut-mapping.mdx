# 色域外処理（Gamut Mapping）

ある色を別の表示機器や色空間で表すとき、元の色が**出力先の色域（表現できる色の範囲）**に収まらない場合があります。色域外処理は、その色を出力先で扱える色に置き換える処理です。色を変えずに表示できる場合と、色相・鮮やかさ・明るさのどれかを変えなければならない場合があります。

単純にRGBの各成分を範囲内へ切り詰める**クリップ**は、元の成分間の比率を壊すことがあります。一方、色域内へ縮める方法には様々な設計があり、知覚的な色相や明るさをなるべく守るものもあります。最適な結果は表示先の色域や映像の内容によって変わります。

## この教材で扱う入力と出力

- **入力**：320×144画素の合成RGB値。出力先を「正規化した線形sRGBの各成分が0〜1に収まる範囲」と仮定します。合成入力には0未満・1超の値が意図的に含まれます。
- **操作**：RGB方向の色差倍率0.5〜2.0倍、合成パターン2種、灰色の基準値0.2〜0.8、表示倍率100%／200%／400%、リセット。
- **出力**：範囲外マスク、成分ごとのクリップ結果、灰色基準値からのRGBベクトルを一様に縮めた結果。両者を表示用sRGBへエンコードした8-bit Canvasで比較します。
- **重要な制約**：範囲外のRGB自体は通常の8-bit Canvasへ直接表示できません。そのため左の画像は「元の色」ではなく**入力が範囲外かどうかのマスク**です。

## 範囲外のRGBを操作して比べる {#try-it}

マスクの赤い部分は、線形RGBのどれか1成分が0〜1の外側にある画素です。中央・右は、同じ数値入力をそれぞれ異なる規則で表示可能な範囲へ収めています。

<GamutMappingPlayground />

1. 色差倍率を**0.5倍**へ下げると、範囲外マスクの赤い領域は減ります。倍率を上げると、範囲外になる画素と色差が増えます。
2. **成分クリップ**は、赤が1を超えたら1に、負の青なら0に固定します。他の成分はそのままです。そのため色の方向が変わることがあります。
3. **灰軸への縮小**は、灰色の基準点から元のRGBへの線分を、RGB立方体の境界に届くまで同じ比率で縮めます。成分間の差の比率を保ちますが、**知覚上の色相・明度を保証する手法ではありません**。
4. 「タイル」で6種類の色方向と4段の色差を並べて観察できます。灰色基準値を動かすと右の結果が変化します。初期値に戻すと帯状パターン、倍率1.5、基準0.5、表示100%です。

## 数字で仕組みを確認する

線形RGB入力が `(1.40, 0.50, -0.20)` の場合を考えます。

| 操作 | R | G | B |
| --- | ---: | ---: | ---: |
| 入力（色域外） | 1.40 | 0.50 | −0.20 |
| 各成分を0〜1にクリップ | 1.00 | 0.50 | 0.00 |
| 灰色0.50を基準に縮小 | 1.00 | 0.50 | 約0.11 |

灰色の基準値を `a = 0.50`、入力成分を `c` とします。縮小では各成分を `c' = a + t(c − a)` と計算します。`t` は0〜1の共通倍率で、全成分を0〜1へ収める最大の値を選びます。この入力では `t = 5/9` です。したがって、入力から灰色までのRGBベクトル方向は保たれますが、結果の見た目が知覚的に同じ色相になるとは限りません。

この実験では**最初から色域内のRGBはどちらの方法でも変更しません**。色域境界を滑らかに圧縮するプロダクション用の処理ではなく、外側の値を境界へ移す最も単純な二例です。

## 色空間変換と混同しない

色域外かどうかは、**どの原色・白色点を持つ色空間へ変換したか**によって変わります。実務ではまず入力色空間を正しく解釈し、必要な色空間変換を行ったうえで、出力先に収まらない色の扱いを決めます。数値が0〜1から外れるだけで入力データが壊れているとは限りません。

本教材は出力側の**線形sRGB立方体だけ**を扱うため、Rec.2020、Display P3、ACEScg間の色度変換を実装していません。ICCプロファイルやホワイトポイントの順応、HDRトーンマッピング、色覚モデルも扱いません。表示モニターやブラウザの色管理により、Canvasの見え方にも差が生じます。

実際の知覚的色域マッピングには、例えばCSS Color 4のOKLChに沿った彩度低減や、ACESの色外観モデルによる複雑な圧縮があります。**ここでのRGB灰軸縮小をCSSやACESのアルゴリズムと同一視しません**。After Effects／DaVinci Resolveに似た設定があっても、処理位置、色管理、内部精度が異なるため、このCanvasとの完全一致は保証しません。
