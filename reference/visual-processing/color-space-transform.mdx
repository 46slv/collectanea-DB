# 色空間変換（Color Space Transform）

同じ `(R, G, B) = (1, 0, 0)` でも、その数値が **sRGBの赤**を表すか、**Display P3の赤**を表すかで、対応する光の色は変わります。色空間変換は、入力値が表す色をなるべく維持しながら、別の色空間で使う数値へ置き換える操作です。単にRGBの3値を別の画像へコピーする処理ではありません。

Display P3はsRGBより広い原色の範囲を持ち、両者ともD65白色点と同系統のsRGB伝達関数を使います。したがって、この2空間の違いを調べれば、**数値の符号化**と**RGB原色の座標**を区別して理解できます。

## 何を入力し、何が出るか

- **入力**：320×144 pxの合成RGB帯、またはRGB混合グラデーション。各成分は0〜1の符号化値で、選んだ入力色空間（sRGB／Display P3）の色として解釈します。実写、ICCプロファイル、カメラRAWは読み込みません。
- **操作**：入力色空間、出力色空間、2種類のパターン、灰色0.5からの彩度方向の強さ0.2〜1.0倍、表示倍率100／200／400%、初期化。
- **出力**：入力の数値を無変換でsRGB表示した**誤解釈の例**、正しく変換して出力色域でクリップした後にsRGB表示へ戻した**近似プレビュー**、出力の線形RGBで0〜1を超えた画素のマスク。代表画素の変換前後の符号化数値と色域外画素数も表示します。
- **注意**：表示の3パネルはいずれも標準的な**8-bit sRGB Canvas表示用の近似**です。P3だけで表せる鮮やかな色を忠実に画面上へ出すための教材ではありません。

## sRGBとDisplay P3を変換してみる {#try-it}

<ColorSpaceTransformPlayground />

初期状態は**Display P3 → sRGB**、6色の帯、強さ1.0倍、100%表示です。色の強い領域ほど、左の「P3の数字をsRGBとして読む」例と中央の正しい変換・クリップの結果が異なり、右のマスクには色域外の画素が現れます。

1. **入力をsRGB、出力をDisplay P3**にします。sRGBから広いP3へ変換した数値は変化しますが、中央のsRGBプレビューは原則として元のsRGB色に近くなり、出力色域外マスクはほぼ空になります。
2. **入力をDisplay P3、出力をsRGB**へ戻します。右の赤いマスクが示す場所は、そのままの色をsRGBで表せません。中央には出力RGBを0〜1でクリップした近似が表示されます。
3. **彩度方向の強さを0.2倍**にすると、灰色へ近づくため色域外画素が減ることを確認できます。入力パターンと表示倍率を変え、細部を観察してください。初期化すると設定はすべて初期値へ戻ります。

## 数値変換の順序

この教材は、各色の符号化されたR′G′B′を直接3×3行列へ入れません。次の順に計算します。

```text
入力の符号化RGB (sRGB または Display P3)
  → sRGB系伝達関数を逆変換して線形光RGB
  → 入力原色の 3×3 行列で XYZ (D65) へ
  → 出力原色の逆行列で出力側の線形光RGB へ
  → sRGB系伝達関数で出力側の符号化RGBへ
```

正の符号化成分 `c` が0〜1のときの逆伝達関数は次のとおりです（負の拡張値には符号対称の延長を使用）。

- `c ≤ 0.04045` のとき：`c_linear = c / 12.92`
- `c > 0.04045` のとき：`c_linear = ((c + 0.055) / 1.055) ^ 2.4`

XYZの **Y** は線形光の輝度成分ですが、映像のY′（ルマ）とは同じではありません。ここではsRGBとDisplay P3がともにD65なので、異なる白色点間の**色順応変換は不要**です。例えばD65からD50、ACES系空間へ移る場合には、白色点や伝達関数を別途考慮する必要があります。

両色空間の原色の違いにより、Display P3の純赤 `(1, 0, 0)` をsRGBの線形光RGBに変換すると、**Rが1を超え、GとBは負**になります。これは行列変換の失敗ではなく、sRGB色域の外にあることを意味します。数値変換そのものは範囲外の値を保持し、Canvasプレビューを作る段階でだけ出力色域へクリップしています。

## 数値が変わっても見た目を保つには

色空間変換の基本的な目的は、出力機器が表せる範囲で**同じ色の意味を保つこと**です。色空間を正しく解釈しないと、同じコード値でも異なる色として描かれます。対して、出力先に存在しない色は、どのように近い色へ収めるかという別の判断が必要です。これが[色域外処理（Gamut Mapping）](./gamut-mapping.mdx)です。

この教材の色域外処理は**RGB成分ごとの単純クリップだけ**であり、知覚的な色相・輝度を保つガマット圧縮を実装していません。P3表示能力やOS・ブラウザのカラーマネジメントによって実際の色の見え方が変わる点も、ここでは検証しません。

## 実際の作業との違い・制約

- **ブラウザ近似**：Canvas上のsRGB 8-bitプレビューでは、P3色域全体・HDR階調・ディスプレイプロファイルを直接再現できません。右のマスクは算術的な範囲外判定であり、視覚上の色差を測るものではありません。
- **変換範囲**：sRGBとDisplay P3の原色・D65白色点・sRGB系伝達関数だけを実装。Rec.709の映像レンジ、Rec.2020、Log、PQ/HLG、ACEScg、ICCプロファイル、トーンマッピング、色順応、アルファ合成、ガマット圧縮は対象外です。
- **After Effects／DaVinci Resolve**：プロジェクトの色管理、入力の解釈、作業空間、ノード位置、表示変換、内部精度によって結果が変わります。この3×3行列とCanvasをAE/ResolveのCST機能や色管理と**完全同等**とは主張しません。ソフト上での具体的な設定値の一致も未検証です。
- **入力素材**：すべて生成した合成パターンで、第三者の画像や動画素材は埋め込んでいません。
