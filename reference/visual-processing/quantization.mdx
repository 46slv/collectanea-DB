# 量子化（Quantization）

量子化は、入力値を決められた少数の値のどれかへ置き換える処理です。白から黒への滑らかなグラデーションを4階調にすると、使える明るさは4種類に限られ、隣接する画素が同じ値に丸められた部分では帯状の段差が見えます。

画像では階調を減らす操作として目に見えますが、量子化という考え方は音声や測定値にも使われます。ここでは画素の明るさを扱います。

## 入力・処理・出力

- **入力**：画素ごとの明るさと、出力に使う階調数（この教材では2〜16）。
- **処理**：各入力値を最も近い出力段階へ丸めます。ここでは黒と白を含む等間隔の階調を使います。
- **出力**：多くの入力値が同じ階調にまとめられた画像。元の値と丸めた値の差が量子化誤差です。

画像を縮小して画素の**数や位置**を変える操作とは異なり、量子化で変えるのは主に各画素が取れる**値**です。

## 操作して比較する {#try-it}

下は[ディザリング](./dithering.mdx)でも使っている比較教材です。左の「01 / 元画像」と中央の「02 / 量子化のみ」を観察してください。初期値では4階調で、中央の画像に段差が見えます。

階調数を**2**にすると黒と白だけになります。**4 → 8 → 16**と増やすと段差が細かくなります。元画像を円形グラデーションへ切り替えると、段差は同心円状に現れます。

右側の「03 / 処理結果」はディザリングとの比較です。「処理方式」を「ディザなし（量子化）」にすると中央と一致します。規則的ディザや誤差拡散へ切り替えると、使える階調数は同じでも画素の配置によって見え方が変わります。

## 数値では何が起きるか

この教材は明るさを0（黒）〜1（白）で表し、黒白を含む等間隔の **L階調**へ丸めます。計算は「入力 × (L − 1) を最も近い整数へ丸め、(L − 1) で割る」です。

4階調なら出力候補は0、1/3、2/3、1です。入力が0.40でも0.30でも、どちらも1/3へ丸められます。

| 入力（0〜1） | 4階調の出力 | この教材の8-bit表示値 |
| ---: | ---: | ---: |
| 0.00 | 0 | 0 |
| 0.20 | 1/3 | 85 |
| 0.40 | 1/3 | 85 |
| 0.60 | 2/3 | 170 |
| 0.80 | 2/3 | 170 |
| 1.00 | 1 | 255 |

0.40が1/3（約0.333）へ丸められると、元との差は約−0.067です。この差を量子化誤差と呼びます。段階の中では入力が変わっても出力が変わらず、境界を越えるところで一斉に値が切り替わるため、帯が見えます。

この式は教材の等間隔・四捨五入方式のものです。出力候補を不均等に置いたり、別の丸め方をしたりする量子化もあります。

## 実制作ではどう使うか

**意図的に面を作る場合**：少ない階調を使って明暗を大きな形へ分けると、ポスタリゼーションやセル調の画面を作れます。元画像の明暗の分布によって、残る輪郭や面の大きさは変わります。

**段差を避けたい場合**：滑らかな空や暗部などで、量子化された階調の境目が帯として目立つことがあります。これはバンディングと呼ばれる現象の一例です。実際の映像では色変換、圧縮、表示条件なども影響するため、段差の原因が単純な量子化だけとは限りません。

**保存精度との違い**：「4階調」を選ぶことと、ファイルを2-bit形式で保存することは同義ではありません。この実験では少数の候補に丸めた後、Canvasへ表示するために0〜255の8-bit値へ変換しています。画素に使う値の種類数と、ファイル形式のビット深度を区別してください。

## この実験の範囲

白黒の静止テスト画像を、ブラウザの表示用にエンコードされた値で処理する簡易教材です。色付き画像の色量子化、作業色空間、ガンマ、HDRや広色域の精度は扱いません。After EffectsやDaVinci Resolveの内部処理・表示結果と一致する保証はありません。最終出力では、画面サイズ、拡大縮小、圧縮によって段差の見え方が変わる場合があります。
