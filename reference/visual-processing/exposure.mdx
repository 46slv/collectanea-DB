# 露出補正（Exposure）と線形光の倍率

露出補正は、画面の明るさを**光の量を増減する考え方**で調整する操作です。+1 EV（1段）なら線形光の値を2倍、−1 EVなら半分にします。すでに白の上限に達した画素では、値の違いが残せずハイライトが同じ白へ集まります。

ブラウザで扱う8-bitのsRGB値は光量そのものではありません。そのまま2倍にするのではなく、**sRGB値を線形光へ変換 → 2のEV乗を乗算 → sRGBへ再符号化**する簡略モデルを使います。

## 入力・出力・操作

- **入力**：384×160画素の表示用8-bitグレースケール。横方向グラデーションと中心が明るい楕円グラデーションから選択。
- **操作**：露出補正 −2〜+2 EV、0.5 EV刻み。初期値0 EV。表示倍率100・200・400%とリセット。
- **出力**：元画像と補正後画像、入力→出力のカーブ、入力32・128・224の変換結果、線形計算で上限1を超えた元画素数。
- **計算**：正規化したsRGB値を線形化し、L' = L × 2^EV とする。表示可能な0〜1へ制限してsRGBに戻し、8-bit整数へ丸める。入力0は常に黒のまま。

## 露出を変えて比較する {#try-it}

<ExposurePlayground />

最初は0 EVで、元画像と補正後は一致します。+1 EVにすると、中間の入力128は176へ移動し、入力224は白255まで達します。−1 EVでは入力128は92、224は164になります。段数が同じでも、符号化されたコード値が単純に2倍・半分になるわけではありません。

| 入力（sRGB 8-bit） | −1 EV | 0 EV | +1 EV |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 |
| 32 | 20 | 32 | 47 |
| 128 | 92 | 128 | 176 |
| 224 | 164 | 224 | 255 |
| 255 | 188 | 255 | 255 |

+1 EVで元の224は上限を超え、元の255と同じ255として出力されます。後から−1 EVに戻しても、いったん切り詰めた255だけから元の224と255を識別することはできません。**白飛び後の画素情報は、この出力だけでは復元できません**。0 EVでの一致と、明るい端で曲線が水平になる様子をグラフでも確認してください。

## 仕組みと、ガンマやコントラストとの違い

sRGBの正規化値をCとし、線形光をLとします。Cが0.04045以下ならL=C/12.92、それ以外はL=((C+0.055)/1.055)^2.4です。補正後のL'を表示域へ収め、L'が0.0031308以下ならC'=12.92×L'、それ以外はC'=1.055×L'^(1/2.4)−0.055として8-bitへ戻します。

[ガンマ](./gamma.mdx)は符号化した値へのべき乗の操作を示す教材で、この露出実験とは処理位置と式が異なります。[コントラスト](./contrast.mdx)はピボットからの差に倍率をかけ、[トーンカーブ](./tone-curve.mdx)は制御点ごとに傾きを変えます。同じ明るさに見える結果でも、暗部やハイライトの値の動き方を比較してください。

## 制約とソフトでの利用

これは**表示向けsRGB・グレースケール・8-bitの教材**です。実写RAW、カメラのセンサー露光、シーン参照の広い輝度範囲、HDRのロールオフ、色管理、色相の変化、RGB間の相互作用は扱いません。負のEVで白が灰色になるのは、この教材の白255を線形化して処理しているためです。

After EffectsにはExposureエフェクトがあり、Exposureはf-stop単位の光量補正です。ただしAEの作業色空間・線形化・ビット深度・他の設定次第で結果は変わります。DaVinci Resolveのカラーツールについても、名称や操作感だけで本式と一致すると断定しません。ブラウザ表示、端末の色管理、量子化誤差によっても見た目は変わります。
