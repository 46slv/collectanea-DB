# 彩度（Saturation）とRGBの灰色軸

彩度を下げると、色の違いが小さくなり、灰色に近づきます。上げると色の違いが強くなります。ただし「彩度」という言葉は、**RGBの値を直接加工する操作、HSV/HSLのS、知覚的な色空間でのChroma**など、同じ計算式ではない処理を指すことがあります。画面上のスライダーの「100%」も、アプリ間で同じ画素値を保証しません。

この教材は「色と無彩色の距離を変える」という考え方に絞ります。入力は合成した表示用の**8-bit sRGBコード値**で、scene-linear光量や撮影素材の広色域値ではありません。

## 入力・出力・操作

- **入力**：384×160画素の不透明なRGB画像。色相が連続的に変わる帯と、無彩色を含む8種類のカラーパッチ。どちらも縦方向に明るさが変わる合成パターンで、外部素材は使用しません。
- **操作**：彩度係数0.00〜2.00（0.25刻み）、入力パターン、表示倍率100／200／400%、初期値へのリセット。
- **仕組み**：各画素の非線形RGBコード値 `R', G', B'` を読み、重み付き灰色 `N = 0.2126 R' + 0.7152 G' + 0.0722 B'` を計算します。各チャンネルを `C'out = N + s (C'in − N)` で更新し、0〜255へ制限・四捨五入します。
- **出力**：処理前・後の2枚の画像、操作中の係数、範囲外へ出た画素の個数、代表的な暖色・寒色・無彩色の入力／出力RGB数値。拡大率の変更は表示だけに作用します。

## 色を灰色から遠ざける実験 {#try-it}

<SaturationPlayground />

1. 最初は係数1.00で、左右の画素が同じです。0.00にすると各画素の3つのチャンネルが同じ数値になり、**モノクロ**になります。
2. 0.50ではRGBコード上の色差が半分に縮みます。1.50や2.00へ上げると色差が増えますが、表示可能な0〜255を超えた成分は切り詰めます。係数を大きくしても、飽和済みの色は変化しないことがあります。
3. 「8色のテストパッチ」では灰色の列にも注目してください。元が `R'=G'=B'` なら、係数を変えても灰色の画素は変わりません。
4. 表示倍率を上げると、色の連続的な変化に対する8-bit丸めの影響が見やすくなります。「初期値に戻す」で帯のパターン、係数1.00、倍率100%へ戻ります。

## 数値で確かめる

入力 `R'G'B' = (180, 100, 80)` では、重み付き灰色値は約115.57です。上の式を適用すると以下になります。

| 係数 s | 出力 R' | 出力 G' | 出力 B' | 観察 |
| ---: | ---: | ---: | ---: | --- |
| 0.00 | 116 | 116 | 116 | 無彩色 |
| 0.50 | 148 | 108 | 98 | 元より色差が小さい |
| 1.00 | 180 | 100 | 80 | 入力と同じ |
| 2.00 | 244 | 84 | 44 | 色差が大きい |

ここで保持しているのは**RGBコード値の重み付き和**です。ディスプレイの物理的な輝度や、人が感じる明るさが厳密に一定である、という意味ではありません。

## 彩度・Luma・Luminanceを混同しない

係数0.2126、0.7152、0.0722はRec.709のY'で使用される重みとして知られ、[W3Cの相対輝度の定義](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance)にも現れます。ただし、W3Cが定義するsRGBの**relative luminance**は、sRGBの伝達特性を逆変換した**線形光**のR/G/Bにこれらの重みを適用します。**本教材はわざとデコードせず、非線形な8-bitコード値に直接適用しています。** したがって、表示上の見た目を理解するための「Y'に似た重み付き灰色の代理値」であり、物理的なLuminanceそのものではありません。

また、HSV/HSLのS、Lab/LCH/OKLCHのChroma、RGBチャネル間の差はそれぞれ定義が異なります。このデモから、特定のソフトのSaturationやColor Boostが同じ結果になるとは推定できません。[W3C CSS Color 4](https://www.w3.org/TR/css-color-4/#color-spaces)は色空間ごとの表現の違いと、sRGB / linear-light sRGBを区別しています。

## 制約と実制作への接続

- 入力は8-bitで、演算後は0〜255へクリップします。**元から白飛びした色や切り詰めた色情報は復元できません。** 0〜2の係数を与えても、実際の出力色域は通常のsRGB表示域のままです。
- 色の見え方は表示装置・ブラウザ・OSのカラーマネジメントに依存します。この教材は合成RGBの画素演算であり、カメラLog、広色域、HDR、線形光グレーディング、肌色保護、色相一定の彩度調整を模していません。
- After EffectsやDaVinci ResolveのSaturation／Color Boost／HSL等と**画素単位の同等性を主張しません**。特定の操作手順を記述するにはソフトのバージョン、入力色空間、処理位置と出力を別途検証する必要があります。

## 参考資料

- [ITU-R BT.709](https://www.itu.int/rec/R-REC-BT.709)：HDTVの測色・信号処理に関する一次資料。教材は一部の重みを参照し、標準の信号経路そのものを再現したものではありません。
- [W3C WCAG 2.2 — Relative Luminance](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance)：sRGBの相対輝度は線形光へ戻して求めることを確認する資料。教材の灰色代理値との違いを示します。
- [W3C CSS Color Module Level 4](https://www.w3.org/TR/css-color-4/#color-spaces)：sRGBと各色空間の特性、コード値と線形光の区別。
- [MDN — CanvasRenderingContext2D.putImageData()](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/putImageData)：計算済み画素をCanvasへ表示するAPI。
