# ホワイトバランス（White Balance）

白い紙や灰色の壁が、室内の電球の下では黄みを帯び、別の照明では青みを帯びて写ることがあります。**本来無彩色であると分かっているものを、画像の中で無彩色へ近づける**のが、ホワイトバランス調整の基本的な考え方です。

実際には光源の分光分布、カメラのセンサーと撮影時設定、RAW現像や色変換の順序が関わります。ここではまず、R/G/Bのチャンネルごとの倍率を変えると、灰色とそれ以外の色がどう動くかを確かめます。

## 入力・出力・操作

- **入力**：384×160画素の不透明な合成sRGBテストパターン。無彩色・肌色に近い暖色・青などの8色パッチを人工的に色かぶりさせた画像と、色かぶりのない灰色グラデーションを切り替えられます。外部素材は使いません。
- **操作**：「寒色 −／暖色 ＋」と「緑 −／マゼンタ ＋」の独立した2軸（ともに−100〜+100、10刻み）、入力パターン、100／200／400%表示倍率、色かぶりを打ち消すプリセット、初期値へのリセット。軸は**ケルビンや撮影時ホワイトバランスの実測値ではありません**。
- **出力**：入力／補正後の2枚のCanvas、線形光で掛けたR/G/B倍率、上限超過画素数、代表的なRGBの入力／出力値。表示倍率だけを変えても画素の演算値は変わりません。

## 色かぶりを戻してみる {#try-it}

<WhiteBalancePlayground />

初期状態では、灰色を含む8色パッチに教材独自の暖色と緑方向の色かぶり（暖色方向+40、マゼンタ方向−20）を加えています。入力の「基準の灰色」はすでにRGBが等しい値ではありません。

1. **「テスト色かぶりを打ち消す」**を押すと、反対の補正（暖色方向−40、マゼンタ方向+20）を掛けます。代表色の灰色がほぼ同じRGB値へ戻り、ほかの色も動くことを比較してください。
2. 暖色方向を＋へ動かすと赤が増えて青が減ります。−ではその逆です。マゼンタ方向を＋へ動かすと緑のチャンネルを減らし、マゼンタ側へ色が寄ります。
3. 入力を**色かぶりのない灰色グラデーション**に切り替え、0/0で無彩色を保つことと、極端な値では灰色が色づくことを確かめます。
4. **初期値に戻す**で色かぶり付きパッチ・補正0/0・表示100%へ戻ります。

このパッチの「人工的な色かぶり」は、現実の照明による撮影結果を物理的に再現したものではありません。また、明るい色は増幅時に上限を超えることがあり、その場合は逆の倍率を掛けても完全には戻りません。

## 計算の仕組み

入力R'G'B'は表示用8-bit sRGBの**符号化された**値です。まず各成分を0〜1へ正規化してsRGB伝達特性の逆変換を行い、線形光のR/G/B（以下L）を得ます。

- 正規化値 c が0.04045以下なら、L = c / 12.92。
- それより大きければ、L = ((c + 0.055) / 1.055) の2.4乗。
- 暖色方向パラメータを T、マゼンタ方向を M とし、ゲインを R: 2^(T/100)、G: 2^(−M/100)、B: 2^(−T/100) とします。これはこの教材が定めた単純なRGBゲインで、色温度や色順応変換の公式ではありません。
- Lにゲインを掛け、1を超えた成分は1へ制限します。次にsRGBの正方向の伝達特性（L ≤ 0.0031308で12.92L、それ以外は1.055×L^(1/2.4)−0.055）で戻し、0〜255へ丸めます。

例えば入力RGB (128, 128, 128) に T=+50、M=0 を掛けると、この簡易モデルの出力は**(150, 128, 109)**になります。0/0は恒等変換なので、灰色だけでなくどの不透明RGBも入力と同じ値に戻ります。

このモデルでいう「上限超過画素数」は、補正中に線形光のどれかの成分が1を超えた画素を数えたものです。チャンネル数でも測光上の白飛び量でもありません。

## 実制作で何に注意するか

ホワイトバランスは色かぶりの原因を推定して調整する作業であり、画像の全体を赤や青へ寄せるだけでは正しくない場合があります。Adobe Camera Rawのホワイトバランスツールでは、白／灰色であるはずの領域を参照して補正できますが、本教材の「色かぶりを打ち消す」は合成時に使った既知の倍率の逆数を指定しているだけで、自動の中立点検出を行っていません。

実際の作品では、基準にする灰色が光源で照らされた**本当に無彩色の被写体か**、複数の異なる色の照明が混在していないか、画像がすでにクリップしていないかを確認する必要があります。意図的に夕焼けの暖色を残したい場合など、画面の全てを機械的に無彩色へ揃えることが正解とは限りません。

**制約**：これは不透明な8-bit sRGBデータを線形光へデコードして単純な対角RGBゲインを掛ける教育用近似です。カメラRAWのセンサーデータ、色温度Kに対する応答、分光特性、色順応行列、D65以外への正確な色空間変換、Log、HDR・広色域、複数光源の局所補正は扱っていません。**After EffectsやDaVinci ResolveのTemperature/Tint/WBと画素単位の一致を主張しません。**
