# コントラスト（Contrast）と明暗差の線形変換

コントラストは、暗い部分と明るい部分の**差の大きさ**です。ここでは基準値（ピボット）を中心に画素値の距離を広げたり縮めたりする、最も単純な**線形コントラスト変換**を扱います。実際のカラーグレーディングには別の曲線や色空間を使う方式もあります。

## 入力・操作・出力

- **入力**：384×160画素の表示用8-bitグレースケール。横グラデーションか、中心が明るい楕円グラデーションを選択します。
- **処理**：入力値 v（0〜255）を、ピボット p と倍率 c で **p + c × (v − p)** に変換します。結果は整数に丸め、0未満・255超を各端へ切り詰めます。
- **操作**：倍率 c は0.50〜2.00（0.25刻み）、ピボット p は64〜192（16刻み）、表示倍率は100/200/400%。初期値は c=1.00、p=128、横グラデーション、100%です。
- **出力**：元画像と処理後を同時表示。代表的な入力64・128・192の出力値と、丸める前の計算値が範囲外となった画素数を表示します。

## 操作して差を比べる {#try-it}

画像を比較してから、下のスライダーを操作してください。

<ContrastPlayground />

1. 倍率を**1.00**にすると元画像と同じです。**0.50**は差を縮め、**2.00**は差を広げます。
2. **2.00**で暗部と明部の画素が黒・白に張り付きます。範囲外画素数を見ながら確認してください。元の情報を復元できなくなる可能性があります。
3. ピボットを128から動かすと、変化の中心となる明るさが移動します。ピボットが同じでも、倍率によって端点が保たれるとは限りません。
4. 元画像の形を切り替え、200%・400%の拡大で段差を観察できます。初期値に戻すと4つの操作値が戻ります。

## 数値で理解する

ピボット128の場合、式は **128 + c × (v − 128)** です。8-bitの範囲外を0・255に切り詰めた値を表に示します。

| 入力 v | c = 0.50（差を縮小） | c = 1.00 | c = 2.00（差を拡大） |
| ---: | ---: | ---: | ---: |
| 0 | 64 | 0 | 0 |
| 64 | 96 | 64 | 0 |
| 128 | 128 | 128 | 128 |
| 192 | 160 | 192 | 255 |
| 255 | 192 | 255 | 255 |

倍率0.50では黒端と白端が灰色に寄るため、画像全体の範囲が狭まります。倍率2.00では入力192の計算値は256なので、出力は255にクリップされます。**「範囲外画素数」は丸め前の値が厳密に0未満または255超の画素数**で、すでに端点だった画素や丸めで端点になった画素の総数とは異なります。

## 何に使い、何と違うか

弱い明暗差の素材に輪郭感を付けたり、全体を柔らかいトーンに寄せたりできます。ただしクリッピングが起きると、暗部の異なる入力が同じ黒、ハイライトの異なる入力が同じ白へ潰れ、後から区別できません。色付き画像ではRGB各成分を単純に変換するか、輝度だけを扱うかでも色の見え方が変わります。

[ガンマ](./gamma.mdx)のべき乗変換は曲線で中間調を動かし、黒・白の端点を保つモデルです。このページの**線形コントラスト**はピボットからの距離を一定倍率で変えるため、両者の階調の変わり方は異なります。また、[量子化](./quantization.mdx)や[ポスタリゼーション](./posterization.mdx)のように段階数を直接指定する処理でもありません。

## 実装上の制約

本教材は**表示用に符号化された8-bitグレースケールのコード値**を演算します。シーンリニアな光量、HDR・広色域、物理的な撮影露光や実機のトーンマッピングを模擬しません。Canvasやディスプレイの色表示、整数丸めも観察結果へ影響します。

After EffectsのBrightness & Contrast／CurvesやDaVinci ResolveのContrast/Pivotが、この線形式と同じ内部式・処理順・色管理で動作すると確認したものではありません。製品別の操作方法は別途検証した時点で扱います。
