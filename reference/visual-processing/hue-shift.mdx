# 色相の変更（Hue Shift）

赤を黄や青へ変えるように、色の**方向**をずらす操作を色相変更（Hue Shift）と呼びます。明るさや彩度を直接増減する操作とは区別できます。ただし、どの色空間を使って角度を回すかによって、同じ「+60°」でも結果は異なります。

このページは**符号化された8-bit sRGBのRGB値をHSLへ変換して色相だけを回す教材**です。知覚的に均等な色変化や、撮影素材のシーンリニア処理ではありません。

## 入力・出力・操作

- **入力**：384×160画素の不透明RGBテスト画像。縦方向にHSLのLightnessが変わる色相帯と、灰色を含む8色パッチから切り替えます。すべてコードで生成し、外部素材を使用しません。
- **操作**：色相回転量 −180°〜+180°（30°刻み）、パターン2種類、表示倍率100／200／400%、初期値へ戻すボタン。
- **出力**：処理前後のCanvas 2枚、現在の角度、代表的な赤・青・灰色の入力／出力RGB数値。倍率は画像の表示にだけ作用します。
- **仕組み**：非線形sRGBのR'G'B'（各0〜255）をHSLへ変換し、Hだけを `(H + θ) mod 360°` に置き換え、SとLの数値を保ってRGBへ戻します。最後に8-bitへ丸めます。

## 操作して確かめる {#try-it}

<HueShiftPlayground />

まず回転量0°では、左右の画像が同じです。+60°にすると鮮やかな赤は黄へ、+120°では緑へ変わります。−120°は赤を青へ移動します。色相帯の端は0°と360°で同じ赤へ戻るため、回転は一周すると繰り返します。

「8色のテストパッチ」で灰色を探してください。HSLのSが0である**無彩色には、回す色相の意味がない**ため、どの角度でも灰色は変わりません。明るさが違う色や淡い色についても、HSLの角度が同じだけ変化することを比較できます。

## 角度の計算と具体例

HSLでは色相は円周上の角度です。純粋なsRGBの赤は0°、黄は60°、緑は120°、シアンは180°、青は240°、マゼンタは300°です。360°は0°へ戻ります。角度を加える場合は負の値も0〜360°に折り返します。

| 入力RGB | 回転量 | 出力RGB | 観察 |
| --- | ---: | --- | --- |
| 255, 0, 0 | 0° | 255, 0, 0 | 元の赤 |
| 255, 0, 0 | +60° | 255, 255, 0 | 黄 |
| 255, 0, 0 | +120° | 0, 255, 0 | 緑 |
| 255, 0, 0 | −120° | 0, 0, 255 | 青 |
| 128, 128, 128 | +180° | 128, 128, 128 | 灰色は不変 |

HSLのLは「RGBコード値の最大と最小の平均」で、**物理的な輝度や知覚上の明るさではありません**。例えばHSLのL=50%を保ったまま赤を青に変えても、画面上の見かけの明るさは変わります。[W3C CSS Color 4](https://www.w3.org/TR/css-color-4/#the-hsl-notation)でも、HSLの色相が知覚的に等間隔でなく、色相操作により視覚的な明るさが変わることが説明されています。

## 実制作での使い分けと制約

色調の方向を変えたい場合はHue Shift、鮮やかさを変えたい場合は[彩度](./saturation.mdx)、画像全体の明暗値を変えたい場合は[トーンカーブ](./tone-curve.mdx)など、まず処理対象を区別します。肌色だけを保ちたい場合のような選択的な操作は、対象範囲のマスクや別の色空間に基づく補正が必要です。

この教材はRGBコード値をHSLへ変換する例で、**HDR、広色域、scene-linear、OKLCHの色相回転、After EffectsやDaVinci ResolveのHue系ツールとの完全同等性を保証しません**。8-bitへの丸めによる小さな誤差が生じます。ブラウザ・OS・ディスプレイによって色の見え方も変わります。
