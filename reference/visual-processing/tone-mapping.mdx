# トーンマッピング（Tone Mapping）とハイライトの圧縮

トーンマッピングは、明るい光源や反射などを含む**広い輝度範囲を、表示できる範囲へ再配置する処理**です。たとえば線形光の値が1より大きい場面で、出力の上限を1と決めて単に切り詰めると、入力2も4も8も同じ白になります。圧縮曲線を使えば、これらを別々の明るさとして出力できます。

この教材は**相対的な線形光のグレースケール値**（0〜8）から出力を計算します。ブラウザに表示しているのは処理後の0〜1を8-bit sRGBへ符号化した画像で、実際のHDR表示や絶対輝度を扱うものではありません。

## 入力・出力・操作

- **入力**：384×160画素、0〜2・4・8のいずれかをピークとする、合成した相対線形光の画像。横グラデーションと中心光源の2種類。Float32値なので入力1より上を保持します。
- **操作**：入力ピーク2／4／8、露出補正−2〜+2 EV（0.5刻み）、入力パターン、表示倍率100／200／400%、初期値へ戻す。
- **変換**：EVを線形入力に乗算したあと、(A) 1を超えた値を切り詰めるか、(B) 簡易Reinhard曲線 `y = x / (1 + x)` で0〜1へ圧縮します。最後にsRGBの伝達関数で8-bitへ符号化します。
- **出力**：切り詰めと圧縮の2画像、両処理の応答曲線、入力値ごとの出力コード、露出補正後に1を超えた入力画素数。**元の広い輝度範囲を、そのまま画面に表示しているわけではありません。**

## 白へ切り詰める場合と圧縮する場合 {#try-it}

<ToneMappingPlayground />

初期状態ではピーク4のグラデーションを使います。左の「上限1でクリップ」では白い領域が広くなり、右の圧縮結果では明部にも緩やかな明暗差が残ります。

1. 入力ピークを2→4→8へ変えると、クリップする範囲が増えます。圧縮側は明るい端が徐々に白へ近づきますが、有限の入力値をちょうど1へはしません。
2. EVを−1にすると、同じ入力値が半分の線形光量として計算されます。+1なら2倍です。**露出補正と圧縮曲線は別の操作**ですが、適用する順番で結果が変わります。
3. 中央に明るいスポットを置くと、クリップで中心付近が平坦な白になり、圧縮で形が残ることを比較できます。表示倍率を変えても処理自体は変わりません。

## 代表値で確認する

露出0 EVで相対線形光の値を変え、最終8-bit sRGBのコード値を比較します。

| 線形入力 | 上限1でクリップ | Reinhardで圧縮 |
| ---: | ---: | ---: |
| 0 | 0 | 0 |
| 0.5 | 188 | 156 |
| 1 | 255 | 188 |
| 2 | 255 | 213 |
| 4 | 255 | 231 |
| 8 | 255 | 242 |

圧縮後の値が「暗く見える」のは、ハイライトの差を残す代わりに、**低い入力値にも同じ圧縮式を適用している**ためです。この演習は映画向けのフィルミック曲線や実際のHDR→SDR変換に必要なすべての処理を再現したものではありません。

## 仕組み・露出補正との関係

まず線形光の入力を `L` とし、露出補正後の `x = L × 2^EV` を作ります。単純なクリップは `min(1, x)`、本教材のグローバルな圧縮は `x / (1 + x)` です。後者は入力が大きくなるにつれて傾きが緩くなり、理論上は1へ近づきますが、有限の正値では1未満です。クリップは1を超えた入力の区別を失います。

この曲線はReinhardらによる写真のトーン再現手法に関連する**単純化されたグローバル曲線**です。原論文で論じられる輝度のスケーリング・画像全体の適応や局所処理などを、すべて実装したものではありません。

[露出補正](./exposure.mdx)では、入力が表示用のsRGB 8-bitであり、一度線形化してEVを適用したあと表示域へクリップします。一方、このページでは**最初から1を超える合成線形入力**を持ち、明部圧縮と単純クリップを比較します。[トーンカーブ](./tone-curve.mdx)は表示用の入力値の対応関係を、制御点で変える教材です。

## 制約と製品での扱い

- この実験は単一チャンネルの相対線形光です。カラー画像の輝度とRGBへの反映、色域外処理、白色点、ディスプレイのnit値、PQ・HLG、HDRメタデータ、シーン参照から表示参照への実際の色管理は対象外です。
- 表示側で8-bitに丸めるので、高精度な入力でも異なる入力が同じ表示コードになることがあります。圧縮側のグラデーションが常に滑らかに見える保証はありません。
- After Effects・DaVinci Resolveのトーンマッピング／カラー管理には異なる演算と設定があり、この**ブラウザ上の簡易Reinhardモデルがそれらと一致すると主張しません**。ソフト別の再現手順は使用バージョンと処理パイプラインを検証してから記載します。

- [Reinhardほか『Photographic Tone Reproduction for Digital Images』（ACM TOG、2002）](https://doi.org/10.1145/566654.566575)：広い輝度を低い表示域へ対応させる写真表現の研究。教材は、その単純なグローバル圧縮の考え方を抽出しています。
- [W3C CSS Color Module Level 4 — sRGB](https://www.w3.org/TR/css-color-4/#predefined-sRGB)：線形光から表示用sRGBへ符号化する伝達関数の根拠。
- [MDN — putImageData()](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/putImageData)：計算済み8-bit画素をCanvas 2Dへ描画する方法。
