# クロマサブサンプリング（Chroma Subsampling）

細かい赤い文字の輪郭がにじんで見えるのに、白黒の輪郭は比較的はっきり残る――その一因になり得るのが**クロマサブサンプリング**です。映像信号の明暗情報（Y′）を細かく保ちながら、色の違いを担う信号（Cb/Cr）の標本数を減らす方式です。

ここでいうY′（ルマ）は、RGBから計算する**符号化された明暗成分**で、物理的な光量としての輝度（luminance、Y）とは別物です。「4:2:0はRGBの色を1/4に減らす」「4:2:2は横解像度も半分になる」は正確ではありません。**半分・1/4になるのは、下記モデルにおける色差の空間標本数**です。

## 入力・出力・操作

- **入力**：赤紫と青緑の交互線を使った192×96 pxの合成不透明RGBA画像。2色のY′がほぼ等しくなるよう選んでいます。
- **操作**：4:4:4／4:2:2／4:2:0、縦線／横線／市松模様、表示倍率100／200／400%、初期化。
- **出力**：元画像と色差の間引き後の画像、Y′とCb/Crそれぞれの標本数、色差の画素共有範囲。
- **観察**：**縦線**は4:2:2でも色が混ざり、**横線**は4:2:2では保たれ4:2:0で混ざります。明暗まで同じになる実写の一般的な予測ではなく、意図的に作った極端な色模様での比較です。

初期状態は**4:2:0・縦1画素の色線・表示200%**です。最初に4:4:4へ切り替えて元画像との差がほぼないことを確認し、4:2:2へ切り替えて縦線の色が平均される様子を見てください。次に入力を**横線**へ変えると、4:2:2では色が残り、4:2:0で平均される理由が分かります。市松模様と400%表示では1画素ごとの差が見やすくなります。

## 4:4:4／4:2:2／4:2:0の違い

この教材は各画素のY′標本を維持し、Cb/Crを次の大きさの**隣接ブロック内で平均**します。表示時はブロック内の画素が同じCb/Crを使います。

| 形式 | 色差を共有する領域 | Y′標本数 | Cb標本数 | Cr標本数 |
| --- | ---: | ---: | ---: | ---: |
| 4:4:4 | 1×1 px | 18,432 | 18,432 | 18,432 |
| 4:2:2 | 横2×縦1 px | 18,432 | 9,216 | 9,216 |
| 4:2:0 | 横2×縦2 px | 18,432 | 4,608 | 4,608 |

この表は192×96 pxの**各成分の空間標本数**で、ビット数、ファイルサイズ、圧縮率を示すものではありません。4:2:0の色差が「各面でY′の25%」とは言えても、映像ファイル全体が25%になるわけではありません。実際の動画はbit depth、クロマ配置、メタデータ、圧縮、フレーム間符号化などの要素に左右されます。

この教材の数値計算では8-bit表示向けRGBを0〜255のR′G′B′として扱い、**Rec.709系の係数**として `Y′ = 0.2126 R′ + 0.7152 G′ + 0.0722 B′` を用います。色差は `Cb = (B′ − Y′) / (2 × (1 − 0.0722))` と `Cr = (R′ − Y′) / (2 × (1 − 0.2126))` です。色差を平均した後、各画素のY′と合わせてRGBへ戻します。平均と最近傍での復元方法を固定し、標本数の差だけに注目できるようにしました。

## 実務でどこに影響するか

色差サブサンプリングは、動画記録・配信・中間コーデックなどで**色信号の空間解像度とデータ量の配分**に関係します。細いカラーテキスト、色だけが切り替わる輪郭、強い彩度の模様では差が目立つ場合があります。一方、明暗差の大きい通常の被写体でどこまで目立つかは内容・表示寸法・復元処理によって変わります。

[ビット深度](./bit-depth.mdx)は**各標本の数値精度**、このページの4:2:2などは**どこに何個の色差標本を置くか**の違いです。10-bit 4:2:2と8-bit 4:4:4の優劣を、1つの数値だけで決めることはできません。

## 再現範囲と制約

この教材はブラウザの8-bit RGBA Canvasへ合成パターンを描画する**教育用近似**です。Rec.709規定の伝達特性とsRGBブラウザ表示の変換、限定レンジ/フルレンジのコード割当て、実コーデックのクロマ位置（siting）、再構成フィルタ、bit depth、HDR、広色域、撮影センサーやエンコーダーの処理を再現していません。WebCodecsの実際の符号化・復号APIも使用していません。After Effects／DaVinci Resolveの処理結果と完全一致する実装でもありません。

また、これは隣接画素のCb/Crを**ブロック平均**する方式です。規格上の4:2:2や4:2:0で使用されるフィルタ・補間は実装によって異なるため、画面上の滲み幅そのものを特定のコーデックの予測として用いることはできません。
